# 回放存储优化与验收

日期：2026-10-05（北京时间）。原始测试文件、报文与测站数值没有改写。

## APP 改动

- 所有平台的历史保存使用增量存档和引用，不在历史存储对象中永久持有全部帧。
- 启动恢复读取事件及测站引用，不预先展开全部测站；播放时才合并、解码测站索引。
- 存档采用压缩 JSON 包装，仍保存完整 JSON；旧 JSON 存档继续可读。
- 编码每批最多一个存档，降低多批同时传入 isolate 的峰值。
- 节点去重采用结构哈希定位候选，再精确比较，保留整数、浮点与有符号零差异。
- 回放导出直接生成 UTF-8 字节，减少整份字符串副本。不修改地图或侧栏布局。
- 未开启的测站仍不录制；APP 原有来源保留，服务端排除策略不套用到 APP。

## 后续导出实现

导出去重索引改为临时 SQLite，Dart 索引缓存与 SQLite 页缓存均有上限。
源检查点始终保留到最终文件刷盘、原子发布完成；共享块只在最后一个引用事件
成功导出后删除。原始报文和测站 JSON 不采样、不舍入、不删字段。

大回放改用 `rhythmquake-replay` v2 和 `station-json-gzip-blocks-v1`。每个原始检查点
以 gzip JSON 块写入 JSON 回放包，连同 SHA-256、接收时间和来源索引；原 gzip 数据
原样保留。v1 及旧的帧数组包仍可读取；v2 需要更新版 APP。128 MiB 限制仍保护
最终文件。Linux 包暂时仍包含 SQLite 运行库，沿用已验证的可移动打包方式。

验收采用独立 Python 标准 JSON 流解析、逐节点内容指纹与磁盘引用表，逐帧核对
审计副本，不在校验时再次把长回放的所有测站对象展开进内存。
已对原始 760 帧、30 MiB 输出文件验证，摘要与原文件一致。

后续服务端实测结果及部署状态另行追加，不将实现或编译成功视为性能验收成功。
