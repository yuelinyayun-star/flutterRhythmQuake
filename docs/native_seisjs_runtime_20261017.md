# SeisJS 实时源与显示投影原生迁移（2026-10-17）

## 正式运行路径

Windows 的 SeisJsService 单例直接启动既有 NativeStationRuntime。原始 WS 字节在原生传输与 Rust 源 actor 之间传递，Dart 不再创建这条源的 WS、心跳、重连或过期定时器，也不接收完整的上游 JSON。

Rust 持有连接、握手期限、30 秒 ping、失败重试、逐站状态、5 秒过期扫描、原始更新时间解释、地图分级与变化签名、OBS 输入投影、侧栏特殊站与当前最大站选择。保留原来的字段含义、站点首次出现时的元数据、插入顺序、同值排名、原始 ID 和时间；仍使用 Intensity 表示实时烈度，未以 Max_Intensity 或 Shindo 替换。

Flutter 接收显示模型及已生成的 OBS 输入，执行状态显示和现有地图绘制。侧栏直接接收 Rust 选好的两项显示对象，不再把完整 SeisJS 表送入摘要 isolate 或返回另一个原生模块计算。地图缩放和像素布局仍属于 UI。非 Windows 及既有回放分支保留原路径。

## 显示合并与历史

全部原始观测逐条解析并更新状态。只有显示投影按最短 16 毫秒间隔合并，避免逐条编码、复制及通知无法逐帧绘制的快照。原始观测计数不因合并减少，输入值和时间不改写。空闲 actor 按下一次过期、心跳、重试或握手期限休眠，网络完成立即唤醒，不为 SeisJS 维持每秒十次的空闲扫描。

历史快照和原文在生产线程编码，按现有系统惰性读取；状态变化不重复生成或替换最后一次观测归档。停止源时移除依赖已经释放 owner 的惰性入口。原有全局历史录制、回放调度及 OBS 规则执行仍属于后续迁移范围；本批迁走源生命周期和源级业务，不将它们算作已经原生化。

## 组件性能测量

初版逐条编码显示结果的 CPU 时间上升，因此未采用该版本作为优化结论。最终版本完成显示合并后，在构建任务结束、相同 DLL 和原始输入下，分别运行三轮独立 Flutter tester 进程，交替顺序比较冻结源与新源。每轮预热后处理 3,500 条未经改写的原始观测，最终 nativeProcessed 均为 3,500，末态均为 7 站。

| 中位值 | 冻结 Dart 源 | 原生源及显示桥 |
| --- | ---: | ---: |
| 处理链进程 CPU 时间 | 0.453125 秒 | 0.125 秒 |
| 从输入到最终显示快照耗时 | 356.615 毫秒 | 61.498 毫秒 |
| 压力批次发出的显示更新 | 3500 | 4 |

该组件 CPU 时间下降约 72.4%，耗时下降约 82.8%。计时包括该测试进程的 Rust 线程和显示模型绑定，不是仅测 FFI 调用。压力输入经原始归档测试入口进入，未包含公网延迟或完整 APP 地图绘制；显示更新合并不等于少处理观测。

进程 RSS 受 JIT、GC 与缓冲保留影响，原生三轮结束约为 182.93、144.30、142.70 MiB；不能据此宣称整机内存已经下降。原生停止后测得剩余跟踪分配 84 字节，源 worker 归零。整机同设置的 CPU、RSS、UI 帧和 GPU 仍需单独验收。
