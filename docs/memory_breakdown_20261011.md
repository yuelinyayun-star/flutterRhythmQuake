# 2026-10-11 整机内存分层与分配调用栈核验

本轮针对上一轮平均 RSS 438.62 MiB 继续定位。未修改产品源码、SDK、上游数据、服务器、安装包或用户正在使用的数据目录。所有运行使用上一轮已冻结的同一个 Windows Profile 二进制，设置数据从原安装目录备份分别复制到隔离目录。

## 438.62 MiB 为什么不能直接作为代码回归结论

上一轮 90 秒原始 OS 采样，去掉前 30 秒后，RSS 在 404.95–478.95 MiB 之间波动，峰值后回落，平均 438.62 MiB。前一轮平均 402.22 MiB 来自不同实时输入及运行状态，没有成对的完整 APP 对照。此前只验证了 DYFI 组件堆和固定绘制批次的改善，没有把整机差额归因清楚，不能说完整 APP 内存已经优化成功。

本轮用**同一个可执行文件**重跑 90 秒，后 60 秒平均 RSS 为 **369.90 MiB**，范围 355.59–400.14 MiB。没有改产品代码，数值仍发生明显变化，说明这些跨次均值包含运行状态和内存回收波动，不能将差额直接归给 DYFI 修改，也不能据此排除其他泄漏。

RSS 包含驻留的共享 DLL 页；它与任务管理器默认“内存”列可能不是同一统计口径。

## 原生工作集分类

第一轮正常阶段不连接 VM 服务，不主动 GC。在 30/60/85 秒对 Windows 工作集页面做分类。页列表采集和 VirtualQueryEx 分类是先后执行，不能当作严格原子快照；本轮每次分类约 0.32–0.38 秒。85 秒有 5.94 MiB 页面在查询时已释放，明确记录为未分类，没有给它们编造模块名。

随后 VM 诊断、GC 完成后的一次页面分类如下，三个分类互斥：

| 驻留页类别 | MiB |
| --- | ---: |
| 进程私有页：含 Dart 堆、原生分配等 | 263.52 |
| DLL、驱动、系统及输入法模块映像页 | 95.07 |
| 文件映射页 | 17.92 |
| 该次工作集页列表总量 | 376.51 |

同次分类结束读取 RSS 为 376.79 MiB，查询期间有少量变化。**不能把私有页 263.52 MiB 全叫作原生引擎内存**，里面包含 Dart 等多个分配器。

正常阶段 60→85 秒出现此前没有驻留的搜狗输入法组件：SogouPY.ime 约 8.90 MiB、PicFace64.dll 约 1.31 MiB、SogouTSF.ime 约 1.30 MiB，另有其他输入法/系统模块及映射变化。映像页合计由 78.47 增到约 95.00 MiB；文件映射由 12.39 增到 17.89 MiB。这是当前运行中确认的外部模块变化，**不是上一轮 438.62 MiB 差额的完整原因**。未关闭输入法或改变系统设置。

## 当前雷达图片

第二个独立进程通过 VM 实际枚举 `dart:ui.Image`，确认 3 个活动句柄具有相同 `_image` 对象身份，尺寸均为 **2882×2161**，持有链到 `_QuakeMapViewState._fanRadarLayerRevision` 及当前 ImageState。

它们共享一张雷达图，RGBA32 的像素量为 **24,912,008 字节，约 23.76 MiB**，不是三份 23.76 MiB。这个数字是像素格式体积，不声称等于该图的全部 CPU/GPU 驻留成本，也不与 Dart 堆或工作集简单相加。

首次图像枚举只按 `Image` 类名匹配，误匹配到同名 Flutter widget 类，结果不能用于图像结论。第二次按类所属库 `dart:ui` 确认后重新测量；原始失败结果保留。

## 具体的临时分配热点

第二轮诊断中，不强制 GC 的查询确认 `_Double` 浅大小约 11.83–21.60 MiB，`_List` 约 18.43–29.09 MiB；同时能观察到堆使用量上下变化。它们不能全部视为长期缓存。

第三个独立进程临时启用 VM profiler，并对 `_Double`、`_List` 开启类分配追踪 12 秒，完成后恢复追踪状态及原始 `profiler=false`。追踪只用于找调用点，不用于报告正常 RSS、耗时或分配总速率。

保存下来的 main isolate Double 样本为 28,284 条，样本实际时间跨度约 **0.809 秒**，并非完整 12 秒；List 样本 7,274 条，跨度约 0.915 秒。存在缓冲覆盖，因此不能按完整 12 秒计算次数/秒，也不能外推某个调用点解释整轮 RSS。

Double 样本中确认：

- `lib/widgets/ui/station_dashboard.dart` 的 S-net 排序比较器：15,099 条分配栈。`selectSnetSidebarTopStations` 先过滤、全量排序，再只取 5 站；排序比较器多次访问 `shindo` 并产生数字装箱。`quake_map_view.dart::_emitStationSummary` 调用该函数，即使最大震度最终不显示，当前实现也先执行完整排序。
- 相机投影：能看到 `pow → scale → latLngToOffset → latLngToScreenOffset/projectAtZoom` 的分配栈；部分来自 DYFI 缩略图国界路径。
- 实时测站解析：`cwa_station_service.dart::_acceptRtsPayload` 的数值解析，以及 `quake_map_view.dart::_cwaLayerSignature`。

List 样本还包含实时帧 `sublist → update → _applyRealtimeFrame`、事件身份解析、JSON 编码以及缩略图边界框列表。这些是已确认的分配调用点，不等于各自独占的常驻内存。

**下一项具体优化目标已经从调用栈定位到 S-net 前 5 站选择与地图投影的重复分配。** 本轮只调查，没有修改这些产品逻辑。仍有引擎、字体、音频、图形及分配器中的私有页未精确逐项归因，不能说剩余内存已经全部查清。
