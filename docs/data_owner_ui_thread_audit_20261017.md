# 测站数据链离开 UI 线程的核验（2026-10-17）

本轮完成 Windows NIED 和 FDSN/SeedLink 两条正式运行链的线程归属调整。现有 Rust 数值内核继续使用，原始报文、GIF、波形、时间、测站值和算法输入均不改写。其他工作区修改、实验资料和迁移前备份保留；未操作云端，未构建 Android。

这不是全部后端已经 Rust 化的声明。连接编排、部分源适配、网格与显示投影仍由数据 isolate 中的 Dart 执行；最终原生边界继续遵守 `native_full_pipeline_boundary_20261016.md`。本轮解决的是这些工作继续占用 UI isolate 的问题。

## NIED

`nied-realtime-data-owner` 持有 Lmoni/Kmoni HTTP、Yahoo、WHEWS 和 Jian 连接及源会话；执行原始图像/数组输入、现有 Rust KA 历史与检测、保持/过期、推算输入打包、历史显示快照、地图变更签名与自动化输入投影。HYP 使用既有持久推算 worker，完整观测窗口保留在计算端，返回当前事件和测站记录摘要。

UI 接收没有活动计时器和 KA 历史 owner 的测站视图，更新图层与卡片。侧栏最大站、区域、排序、FFI 缓冲、目录以及显示签名由 `station-summary-data-owner` 持有；最后一轮进一步改为只传变化的台网，未变化的数据留在摘要端，实时/回放切换重建会话。

原始 GIF 调试入口仍存在，直接进入数据 owner；停止、切源、禁用推算有代次检查。回放原始快照的日期解析和数值打包也移到推算端。真实 NTP 样本在启动及同步更新时传入数据端，不改动原观测时间。

运行验证发现 Windows 的后台资源通道返回异常会阻塞地名文件加载，已改为在数据线程读取安装包内的原始 UTF-8 资源文件。随后 Jian 连续收到 1749 站，正式目录路径、检测和推算线程正常工作。

原始物理量 GIF 与旧完整图像解码的数值、缺测标记一致；原始 51 帧对照还覆盖了透明像素及“有震度、无颜色位置”的旧调色表分支。后台传输保留该分支，避免把原来可用的观测变成缺测。

## FDSN/SeedLink

第一轮完整界面采样确认，旧链虽然调用 Rust 解码和滤波，`_SeedLinkConnection` 的连接、收包、数据分包与 FFI 调用仍发生在主线程。

新增 `fdsn-realtime-data-owner`，在其中运行现有生产连接服务、目录与通道校准服务、协议与重连、原始包解码、Rust 信号内核、不同通道观测合并、旧报拦截、最新观测、三分钟保留、地区来源优先级和地图站点筛选。UI 每秒接收准备好的地图列表、状态、连接数和自动化输入；不接原始包，不持有完整目录，不再按包处理。原有绘图样式、测量值与时间不变。

接源、改订阅数量、禁用、后台暂停、恢复和销毁均使用该 owner。非 Windows 及 Android 托管分支沿用原链。原服务保留用于数据端、离线参考和原有测试，Windows 地图不同时启动一份原服务连接。

主线程采样约减少 64%，其热点已从 SeedLink 收包、分包和信号调用转为 Flutter 布局/绘制及跨线程显示传输。该比例是主线程活跃样本的变化，不能称为整机 CPU 降低 64%。实时波形内容和选站集合也不是完全相同的冻结输入。

总 CPU、工作集以及 P95 绘制耗时没有下降，不能宣称卡顿已彻底解决。两轮均开启 VM CPU 采样，取样与转储也会增加内存。后续重点包括地图绘制、显示对象传输/分配，以及仍在 Dart 数据端的业务编排与完整原生所有权。最终的增量摘要改动通过回归，但不计入上表的性能结论。
