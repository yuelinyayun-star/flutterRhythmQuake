# NMEFC 大陆沿海县市岸线

上一轮资产和Rust省份匹配均仅支持台湾省，本轮补齐大陆沿海。
按用户选择的县市一级岸线展示约定，将 `forecasts[].province` 和 `forecastArea`
共同匹配行政岸线，地区颜色仍完全取该行 `warningLevel`，不使用全局等级覆盖地区等级。
这属于APP行政岸线显示范围，不是NMEFC直接发布的警戒边界或淹没区域。

当前全部名称见 `assets/maps/nmefc.named-coasts.provenance.json`。

## 几何与原始来源

1. 海岸轮廓来自APP正在使用的 `assets/maps/ka/cn.province.topo.json`，SHA256
   `4b64a2d342c1017b1b571a4e02c92bafac0e114e9f3c31860b1b1bba4dc56965`。
   读取原始拓扑弧，合并后只取大陆海侧外缘和近岸岛屿外缘，不输出内陆行政边界。
2. 城市划分来自已有 `assets/maps/中华人民共和国.geojson`，SHA256
   `a268d74d3fba89bcc35f9febd8843a9cb77792a3690044dc8b26f21e8acf1bcd`。
   天津、上海及港澳按整市/特别行政区岸线处理。省份名称沿用已有行政索引。
3. 为避免把丹东、防城港后面的陆上国界也当作海岸，使用Natural Earth原始资料的两个
   河口端点作为截断参考，投影到既有底图轮廓；不导入外国行政线或改变底图。
   ZIP保持原字节，来源和哈希见 `references/region_data/natural_earth/README.md`。
   两个参考点在不同尺度底图上的投影距离约0.000173度、0.052939度，详细坐标保留在
   provenance，不能把这种显示级对齐描述成官方海岸界点。
4. 使用现有市界切分底图岸线。两份地图尺度不同而留下的岸线碎段，按同省最近市域
   归属；片段中点最大距离约0.011595度。构建上限为0.02度，超过立即失败，不静默扩展。
   派生叠加网格为1e-9度；2e-9度缓冲仅用于浮点验证，不输出到资产。

## 运行链路

`原报文 → Rust NMEFC解析 → Rust具名岸线匹配 → 现有TsunamiRegionLayer描边/闪烁`。

- 删除“省份必须是台湾省”的硬编码，改为每条岸线的省份全称/简称/简繁体别名匹配。
- 例如浙江/温州对应浙江省温州市，广西/防城港对应广西壮族自治区防城港市。
- 同一行政岸线仅画一次，重复行取报文明示的最高地区颜色。
- 省份冲突、歧义名称、未知等级及解除地区不激活岸线。
- 撤销整报沿用原有逻辑清除图层。
- Dart运行时代码没有新增计算、连接或UI改动；它继续传原文和资产字节、渲染结果。
