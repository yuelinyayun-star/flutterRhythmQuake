# P-Alert 原生观测链迁移与验证

## 续接核验与完整推算迁移（2026-10-18 下午）

本节更新下方前一阶段记录。Windows 的 P-Alert 目前已由 Rust 持有实时连接、原文解析、等级保持、检出、过期、完整 HYP 推算会话和最终展示投影。Dart 负责绑定最终显示对象与分派已有 UI 回调；实时推算不再进入 Dart HYP worker。显式 Dart 参考实现仅用于一致性测试和非原生平台。

- 实时展示使用原生数值列和目录修订，移除了 UI 端的实时 JSON 解码。
- 推算的拾取、邻接、分簇、合并、四阶段搜索、震级和会话结束均在原生所有者执行，沿用原算法。没有采用另一个聊天中仍在研究的 grid rescue / family veto 候选算法。
- P-Alert 回放使用独立原生会话。原始压缩归档由原生校验 SHA-256、解压、解析为不可变共享树，再将原始缓冲和帧节点直接交给原生推算；Dart 不展开并重编码全站输入。
- KMA、TREM、SeisJS 同步使用原生准备的不可变展示/历史数据。P-Alert 的显示确认号将历史与原文锁定到实际送达的同一帧。
- 历史快照直接由原生展示列写入已有二进制树格式，不再先构造 787 个测站 JSON 对象。JSON 键、值、未知值语义、时间和历史外部格式保持兼容。
- 原生回放复用不变的目录；归档带有确认站 ID 时借用原始测站行，不再每帧复制全站对象。未携带确认 ID 的既有检测路径保留。
- 补齐 CMake 对 `knet_batch.rs`、`knet_features.rs`、`whews_auth_block.rs` 的依赖，避免增量构建遗漏。更新所用缓存依赖的许可证文本。

Chat 续接已有工作的核验：跨测站回归日志为 38 项通过、1 项跳过；最新代码联合核验为 26 项通过、1 项跳过，包括 K-NET 数值和 GQ 回放侧栏倒计时。K-NET 当前是离线波形工具路径，不把它的迁移记为实时主界面 CPU 收益。完整测试套件此前存在未通过项目，本节不宣称全套测试通过。

## 前一阶段范围

Windows 的 P-Alert 实时连接由 `NativeStationRuntime` 的 Rust 所有者运行。原始 HTTP 响应不再进入 Dart 数据 isolate 后解析。原始元数据和测站报文保留原值，显示投影与原文分别持有。

Rust 负责 GraphQL 请求、每次连接获取一次测站目录、重试、源时间去重、PGA/PGV 解析与等级保持、KA 历史、联合检出、失效、语音信号选择、格子坐标、地图签名、OBS 测站输入和侧栏最大值。地图复用原有颜色、格子样式与闪烁效果。Dart 只绑定这些准备好的展示值并分派现有回调。

HYP 推算的原生计算内核继续使用；P-Alert 推算会话的 Dart worker 编排仍然存在，本轮没有把整套 HYP 状态机迁入 Rust。地图将原生准备好的输入快照交给已有推算 owner，主 isolate 不再为此扫描全站并重新整理确认站 ID。回放仍使用独立状态与原始归档时间。

移动端和 Web 的既有路径保留；Windows 原生路径出错不会自动启动另一条 Dart 数据处理连接。没有构建 Android，也没有修改云端服务。

## 减少常驻和每帧工作

- P-Alert live actor 按下一次轮询、请求超时和过期时间等待，HTTP 回调立即唤醒，不使用固定 100 ms 空转检查。
- 邻接关系最多保留 6 站及联合检出实际使用的配对距离，避免保留全站 N×N 距离矩阵。
- 历史与原文在原生所有者持有，只有请求归档时才在 Dart 展开；显示快照不携带原始报文。
- 展示序列化借用测站字段，避免每帧深拷贝整份测站 JSON；历史快照复用已序列化的展示帧。
- Dart 每帧绑定重复展示时间时只解析一次，缓存在回调结束后释放，不积累历史帧。
- 回放解码忽略实时展示的 `mapRecent`，继续按回放观测时钟计算鲜度。

## 代理与停止

实际遇到 WinHTTP 12011：自动代理 session 不能接受这里的显式请求代理选项。P-Alert 所有者保留系统自动代理 session 和独立显式代理 session，根据环境代理、NO_PROXY 或系统代理选路。普通源现有 session 行为保留。

系统代理与环境代理均使用官方 P-Alert 实时服务验证：787 站、至少 2 个递增源时间报文、状态 connected。测试没有修改系统代理设置。官方直播原文及日志保存在本轮本地审计目录。无效 JSON 元数据会重试；连续三次 HTTP 失败清理检出并显示具体错误；不会持续重取测站目录。

停止后原生 source worker、HTTP 请求与 client 计数均归零。自动代理与显式代理的底层 session 同时关闭。

WinHTTP 参考：[WinHttpSetOption](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsetoption)、[Option flags](https://learn.microsoft.com/en-us/windows/win32/winhttp/option-flags)。

## 组件性能对照

同一份原始报文通过本机 HTTP 服务进入生产连接 owner。每轮预热一次，再重连 3 次，每次处理 17 个不同源时间帧，合计 51 帧。轮询间隔统一为 40 ms，报文内容和源时间不变。依次交替执行旧 Dart owner 与 Rust owner，共 3 轮。两边都包含地图签名、OBS 展示输入与侧栏最大值准备；不包含地图实际绘制和 HYP。

| 轮次 | 旧路径进程 CPU 用时 | 原生路径进程 CPU 用时 | 旧路径峰值 RSS | 原生路径峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1.141 s | 1.328 s | 230.75 MiB | 212.87 MiB |
| 2 | 1.250 s | 1.313 s | 229.23 MiB | 212.82 MiB |
| 3 | 1.109 s | 1.406 s | 233.78 MiB | 214.00 MiB |

这是整个 Flutter tester 测试进程的 CPU 累计时间与峰值 RSS，包含回环 HTTP 服务；不是任务管理器里的 APP CPU 百分比。所有轮次均收到 51 帧，停止后 owner、请求、client 归零。原生路径测试进程峰值较低，但 CPU 时间仍较高，不能报告 CPU 优化成功。

本轮去掉的深拷贝、重复序列化和时间绑定只减少了原生新链路自身的开销，尚未使 CPU 对照优于旧路径。后续应继续测量原生展示投影的序列化/绑定以及 HYP 编排，不应重复修改已核验一致的检出公式和阈值。整机 Profile 占用与主界面帧率仍须另外采样。
