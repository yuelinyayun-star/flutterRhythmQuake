# NIED 数组观测与原生摘要直连（2026-10-17）

本轮继续移走地图入口里的数据处理，覆盖 Windows 上 WHEWS／Jian NIED 数组观测的 KA 计算链。完整数据后端仍遵守 `native_full_pipeline_boundary_20261016.md`，没有将本轮组件完成等同于全部来源迁移完成。

## 运行路径

既有源适配后的原始数组、原始数据时间 → 薄 FFI 输入 → Rust 有效值判断、断帧处理、KA 历史、异常站恢复计数、上升量、触发时间与活动度 → 显示字段绑定及原生摘要消费。

- 复用已有 `ka_history.rs` 算法；WHEWS／Jian 数组路径不再逐站调用 Dart KA 历史算法。
- Rust 持有最近 60 个 KA 历史值、上一数组帧时间及异常站恢复计数。异常计数仅初始化或显式导入状态时写入，普通帧不从 Dart 视图取回上一帧结果作为计数输入。
- 原始值的既有有效范围保持为有限数且 `-3 < shindo <= 7`；无效值不改写报文，沿用 KA 的缺测与显示保持规则。原始连续震度只在有效输入时更新显示视图。
- 原生按原来的取整顺序计算断帧数、最多补 60 项缺测历史；大于 10 秒的断帧清除活动标记，保持既有行为。原始时间、坐标、数组顺序及原文不修改。
- 摘要在静态目录配置后直接读取 KA 原生输出缓冲，不再把等级从原生复制到 Dart 后重新封装成等级数组送回原生。当前检出保持仍由未迁完的检出服务维护，因此这里只提交每站一个活动标记；没有宣称这部分计时已迁移。
- Dart 只负责本单元的 FFI 输入与显示结果绑定；PGA/PGV 字段和缺失标记沿用原显示视图。上游连接与适配、下游检出/推算业务编排仍是后续迁移范围。

正式地图入口通过 `NiedArrayObservationProcessor` 管理会话；目录替换、源停用与地图销毁释放原生资源。检出重置同步清空原生 KA 状态，摘要不会读取重置前的结果。时钟重置可单独执行，不丢弃既有历史。实时与历史回放的摘要继续隔离；历史显示不借用实时数组的原生缓冲。

借用原生结果只允许同步消费，不保留指针；借用期间拒绝修改或释放生产者。已展开或归档的历史快照拥有自己的数据，停止后原有测站视图仍可读。

本轮前备份：`tmp/nied_array_native_before_20261017_004110`。未修改云端、信息源烈度规则或 UI 布局，未构建 Android。

## 验证

- Rust 全组 38 项通过，包含整帧预检失败不改变时间/历史、补缺测顺序、清除活动标记和时钟重置。

- 边界测试另行使用明确标记的受控输入，覆盖无效浮点数、边界震度、断帧取整、倒序/重复时间、恢复计数、原生缓冲借用、重置与释放，不作为真实地震数据或性能样本。
- 20 次目录配置、处理、清空后，原生会话数与 Rust 当前分配字节返回调用前基线；保留的历史快照不受后续释放影响。

- 最终 Windows 正常入口 Profile 构建通过，输出 DLL 与基准测试 DLL 的 SHA-256 完全一致。未替换当前运行的 Debug；需要完整重启并加载新 DLL，热重载不能替换原生库。
