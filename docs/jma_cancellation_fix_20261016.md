# JMA 取消报接纳修复

事件 `20261016123810` 的原始包有 42 条普通电文和 1 条取消电文。普通第 42 报发布时间为 2026-10-16 12:48:10 JST；取消电文发布时间为 12:48:50 JST，报号为 37，正文没有震源要素。

## 已确认的拦截点

1. 统一前后台入口将取消报的 20 秒显示时长与发震时间相减，晚到的取消报在进入 UI 前即被当作过期。
2. 只允许报号递增，取消第 37 报无法替换已经处理的第 42 报；同报号的 Wolfx 取消也不属于原先允许的正文修订。
3. 已自动过期或关闭的事件被永久挡在当前卡片外，后续取消无法更新终止状态。
4. 历史按报号排序，而且同报号会覆盖原来的条目，导致取消 37 排在普通 42 后，并丢失原普通 37。
5. FAN 在统一适配之前直接跳过 JMA 取消；WHEWS 的去重键没有区分同一 ID、报号、时间的取消状态。
6. JMA Wolfx 的 `AnnouncedTime` 没有进入统一发布时间；FAN JMA 的更新时间应优先于创建时间。

## 行为

- 同一事件的显式取消优先于报号，不伪造递增报号，仍显示原始第 37 报。
- 取消报按发布时间判断新鲜度；没有新的发布时间或沿用普通报发布时间时，只允许关闭最近已经观察到的事件，旧的未知取消快照不会重新弹出。
- 已过期普通报的后续取消仍可接纳。取消卡从本次接纳开始显示 20 秒，重复源不会续期。后台交接只恢复剩余显示时间。
- 已取消事件的普通报、重复取消不会重新激活 UI、波圈或播报。终止状态有独立的有界持久化记录，最高报号不会因取消报号较低而下降。
- 历史以取消为最终状态，保留普通 37 与取消 37 两份原文，最高报号仍为 42。
- 回放按原始发布时间排序，取消的较低报号不使完整时间线退化为手动回放，统一 UI 的回放更新也接受终止状态。

## 验证方式

`test/jma_cancellation_regression_test.dart` 使用原始 ZIP 和原始 Wolfx 响应，覆盖 43 条电文的前后台接纳、完整计时回放、真实统一卡片渲染、20 秒消失、重复去重、终止状态持久化、后台交接剩余窗口以及历史原文保留。官方电文参考映射与 FAN/WHEWS 协议投影在测试与样本说明中明确区分。

原始 ZIP 和线上响应的 SHA-256 都在测试中核验。未向实时数据源注入本次历史误报，未改动云端或运行中的安装版。

最终相关回归共 108 项通过，覆盖取消、双源突发更新、前后台交接、历史保留与联动回放、统一卡片及 EEW 语音队列。历史联动测试原先固定等待 100 毫秒，已改为等待实际历史恢复完成，消除并发测试时未加载完整历史就开始回放的竞态。
