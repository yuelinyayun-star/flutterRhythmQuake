## 实现与资源归属

同一个 `rq_station_core.dll` 增加独立触发 ABI 1，结构及状态码见 `native/station_core/include/rq_station_core.h`。原始字符串站号仍在 Dart，通过稳定且可复用的索引对应原生状态，不修改站号或复制成另一套字符串目录。输入保留 Int64 微秒时间、原始信号和有效标记，输出保留状态、原因码、activity、ascend 和首次上升/触发区间。每个区间端点分别保留 UTC/本地标志。

Rust 保存唯一数值历史，连续时间按队首过期，乱序时稳定过滤，截止点本身保留。基线在加入本帧前求值，与原实现一致。整数单桶中位数直接求精确值；其他整数按直方图，非整数使用可复用排序缓冲，沿用原浮点运算语义。输出没有使用容差替代一致性核验。

Dart 复用连续 Int64/Float64 输入输出缓冲；同一物理缓冲的不同视图不复制。固定站序复用索引，改变顺序时按原站号查找。Dart 只缓存不变的只读显示区间，避免每帧重建相同 DateTime/区间对象，不再保存第二份数值历史或连续帧状态。返回快照不引用原生缓冲，后续缓冲复用或销毁不会改变已返回结果。原因码集合保留原可变集合行为。

单站重置释放原生样本、清除区间缓存并回收索引；全量重置销毁会话与缓冲，下帧按需重建。后台通过关闭消息完成当前同步调用后释放驱动再退出，启动 ready/spawn 竞争也不直接杀死已配置的原生会话。会话和调用者缓冲另有 NativeFinalizer。协议错误会报告，不能自动重试整个批次，否则会重复应用已成功处理的前序行。

原生索引与批次上限均为 1,048,576。`rq_station_memory_*` 现在统计整个 DLL 的请求分配，包括持续触发状态；会话运行时非零是正常持有，不能按首阶段“单帧解码结束归零”的口径判漏。`triggerCalls` 是内部诊断计数，与地震警报报数无关。

## 模块性能与内存

同一冻结 Profile 验证程序，分别在 3 个独立进程中运行旧/新实现，交替顺序。每进程测 5 批，每批为原始 51 帧重复 5 次（255 帧），各实现共 15 批。每段原序列开始前重置状态；不改时间、不放大观测、不丢帧。计时包含输入封装、原生处理和 Dart 快照输出，属于组件端到端墙钟耗时，不能称为整个后台 CPU 降幅。测量期间没有编译或另一套计算并行运行。
