# GlobalQuake 连接流解析迁移（2026-10-15）

Windows 的 GlobalQuake Java 对象流解析已接入 Rust；TCP/TLS 连接建立、代理、订阅与握手字节、心跳、事件转换、首报震级过滤、报数、语音和 UI 仍由既有 Dart 逻辑处理。Android 等平台继续使用 Dart 解析器。本轮没有改 SDK、云端、原始抓包或事件数值。

## 备份与迁移范围

原文件和哈希清单：`build/performance/backups/gq-transport-20261015-084348`。原解析器冻结在 `test/support/global_quake_decoder_before_20261015.dart`，仅添加测试调用包装和剩余字节查询，没有改解析算法。

原 Dart 每次收包复制剩余字节、每个对象复制整份 Java 引用表，逐字段创建临时字节数组，并用 BigInt 读取 Int64。Rust 现在持有连接内的字节缓冲、Java 句柄和协议图；不完整对象只回退新增节点和句柄。TC_RESET 后压缩旧图，避免持续重置时累积旧对象。

输出使用二进制对象图，保留 Int64、Float64 位、引用、自引用、数组、类描述符、集合自定义块及顺序。字符串保留输入字节，沿用原 Dart UTF-8 解码行为。Dart 在同步调用内重建短生命周期业务对象，块数据复制后使用；借用指针不进入历史、事件、isolate 消息或 UI。Rust 不接管统一事件的合并和过滤。

原生 ABI 版本为 1。每连接一个 owner，输入/输出上限 64 MiB、节点上限 100 万、深度上限 256。异常包中止当前连接并按既有五秒规则重连；不在损坏的协议状态上继续解析。主动断开、远端断开、错误和重连均显式释放 owner 与 FFI 缓冲。连接代次校验阻止已取消的异步连接重新安装旧 socket。

Dart 路径同时修复流头与首个对象在同一接收中被截断时，重试把流头误当对象 token 的问题；有效对象的字段处理规则没有变化。

## AOT 性能

同一 Dart 3.11.0 AOT 程序，交替顺序运行三轮取中位数。每轮重复 15,000 次，解出 135,000 个对象。计时包含 FFI、原生解析、Dart 图重建和显式清理，不包含磁盘读取、JSON 快照、UI 或语音。

| 工作量 | Dart | Rust + FFI | 耗时下降 |
| --- | ---: | ---: | ---: |
| 每次新建连接状态，输入完整原始抓包 | 963.759 ms | 809.134 ms | 16.04% |
| 同一抓包分成 64 字节块接收 | 3572.074 ms | 1124.845 ms | 68.51% |
| 同一连接、完整对象边界 TC_RESET 后连续输入 | 748.519 ms | 634.362 ms | 15.25% |

性能基线的 Dart 数值/引用解析循环与原实现一致，仅包含上述首包分片修复，使两侧能够处理相同分片。连续重置是协议压力负载，不是实际收到 135,000 条在线事件。各轮对象数和校验和相同。

组件 RSS 约 16.4–17.0 MiB，没有证明内存下降。分片场景收益明显，完整接收收益较小；不能把这些数字当成 APP 总 CPU、GPU 或主界面帧耗时改善。

可复现脚本：`tools/benchmark_global_quake_stream.ps1`。它从当前生产解析器生成独立 AOT 测量入口。三轮原始记录和 SDK/DLL/原抓包哈希位于 `build/performance/global_quake_stream_comparison_20261015.json`。
