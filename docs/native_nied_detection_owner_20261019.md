# NIED 显示检出状态迁移（2026-10-19）

本轮迁移生产 Windows NIED 数据隔离区中的显示检出状态管理。原先 KA 关联计算已经调用 Rust，但活动保持、到期、格子汇总、通知判定、事件状态和输出去重仍常驻 Dart。本轮将这些职责合并到 `native/station_core/src/nied_detection_state.rs`，由同一个原生会话管理。

## 正式路径

原始观测采样/KA 历史 → 原生显示检出会话 → 测站显示增量、检出格子、事件投影、通知指令 → Dart 薄桥绑定现有显示 DTO → 原有 UI。

- 保留原始邻站关联和阈值规则，保持 10,500 ms 活动期限。
- 期限由原生单调时钟及条件变量调度；没有 Dart 每站保持 Timer，也没有该分支的 2 秒检查 Timer。
- 到期先发布测站活动字段变化，16 ms 后合并发布格子和事件变化；真实新帧会取消这次待合并发布。
- 格子偏移、聚合、测站排序、0 震度有效格子、提示档位、首次聚焦、结束判定、事件开始时刻、快照去重均由 Rust 决定。原先逐站拼接的地图刷新签名也由 Rust 输出，Dart 不再为它遍历目录和排序格子。
- 接收原采样器的缺帧/时间倒退撤销信号。立即重新检出时也确认该测站状态，避免原生状态与显示对象分离。
- Dart 仅写入未经改写的数值列、绑定原生准备的显示结果、格式化显示时间/事件 ID，并执行既有回调。
- 同一目录替换显示对象时仅重绑原生状态，期限继续由原生会话保留。重置清除待发结果；停止关闭端口并唤醒、加入原生线程，释放会话和缓冲。
- 实时、回放及不同数据 owner 各自创建会话，无共享检出事件状态。没有修改原始报文、GIF、测站数值或源时间。

非原生平台的既有分支及 P-Alert 离线参考仍保留。Windows 正式 `NiedRealtimePipeline` 使用新会话，不运行旧的 Dart 格子/通知/保持逻辑。

## 验证

迁移前源文件和 DLL 的备份及 SHA-256 清单：`tmp/nied_detection_owner_20261019/before-manifest.json`。

冻结参考：`test/support/shake_detection_before_20261019.dart`，规则代码与迁移前一致，仅移除生产归档副作用以避免类型和双写问题。

`test/native_nied_detection_owner_test.dart` 使用本地原始奈良样本的 51 张 GIF，共 1,634 站：逐帧核对 83,334 个测站显示状态、原始输入列、格子键/坐标/级别、41 个显示投影、事件身份/时间/成员/状态、5 个通知/聚焦指令及 51 帧完整地图刷新签名；原始文件 SHA-256 不变。检查新链路没有每站 Dart Timer、同目录对象替换维持状态。

额外生命周期检查使用明确标记的接口边界输入，不作为地震测量样本：10,499/10,500/10,516 ms、重置取消待发、真实原生线程独立发布到期并在销毁后返回原会话/线程计数。

`test/nied_realtime_pipeline_test.dart` 覆盖原始物理量 GIF、1,560 站 WHEWS 输入、缺帧恢复、归档至 UI 投影、51 帧至 40 次 HYP 推算及源切换释放。缺帧恢复首次复测发现原生遗漏原采样器撤销活动信号，补齐后通过。

最终 Flutter 定向测试 22 项、Rust 状态管理测试 2 项通过；涉及的新增 Dart 绑定与显示检出文件静态分析无错误。

最终 Windows 正常入口 `lib/main.dart` 的 Profile 构建通过，产物位于 `build/windows/x64/runner/Profile`，不是网络诊断专用入口。构建记录、原始帧对照输出、静态分析和 Rust 结果保存在 `tmp/nied_detection_owner_20261019/`。本轮只做构建验收，没有启动应用连接在线源，也没有生成新的安装包。

最终一次并行测试运行中的入口计时：迁移前显示检出 `processUpdate` 累计 156,684 μs，新路径累计 80,475 μs。包含 FFI、显示绑定和测试回调，不包含目录初始化、网络、采样、HYP、归档、地图绘制。新入口还包含已经迁入的地图刷新签名生成，旧入口的签名生成在外部，未计入旧值。因此该记录仅作组件诊断，不能当作等边界性能验收、整机 CPU/RSS 改善或完整迁移验收。

## 尚未迁完的边界

本轮不等于 NIED 全链路原生化。`NiedRealtimePipeline` 中源连接与协议调度、采样/KA 与显示 owner 之间的中间对象、HYP 调度、历史/OBS/UI 总投影组装仍有 Dart 处理。原生数值/状态模块之间仍存在经 Dart 传列的边界，后续应并入原生源 actor，最终只向 Dart 推送有限显示结果。

未修改云端、API 字段协议或 UI 样式，未构建 Android。
