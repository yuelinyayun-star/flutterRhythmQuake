## 决定与范围

在当前 Flutter 3.41.1 / Dart 3.11.0 上继续完成有证据支持的优化，同时启动 Rust 数据核心的分阶段验证。Flutter 保留统一 UI、地图绘制、设置、语音和平台集成；将批量解码、测站状态、历史窗口及检出/震源计算逐步移入同一个原生会话。暂不重写 WS/HTTP 订阅、事件合并、标题、报数或机构过滤规则。

已按此计划备份并接入 Windows x64 的 NIED 后台图像解码、测站像素采样、通用稳健测站触发器的持续历史和状态，以及 Lmoni KA 测站等级历史与 ascend/activity 运算；HYP 的批量 JMA2001 走时插值、P/S 判相与数值评分，以及 NIED 观测窗口的数值存储与紧凑历史传输也已接入。原始数据、构建与组件测量记录见 `docs/rust_station_core_migration_20261011.md`、`docs/rust_station_trigger_migration_20261011.md` 和 `docs/rust_ka_history_migration_20261011.md`。物理观测元数据、KA/HYP 空间主检出及完整震源搜索状态仍待迁移；尚无完整 APP 常态 RSS 已达到目标的结论，不能以组件结果代替整机验收。

选择 Rust 的工程依据：当前机器已实际执行 `rustc --version`、`cargo --version`，分别为 1.99.0；已安装目标为 `x86_64-pc-windows-msvc`。首模块已锁定并构建 21 个依赖，完成 DLL 链接、FFI 和原始图像输出等价性验证。Android NDK 28.2.13676358、29.0.14206865 已在磁盘确认；Rust Android 目标尚未安装，不能称安卓构建已就绪。初版仅验证 Windows x64，再补 Android arm64，其他 ABI 按现有 APK 支持范围确认。

Dart 可通过 `dart:ffi` 调用 C ABI；Rust 导出 C ABI，避免在边界传递 Rust 内部容器。参考 [Dart 官方 FFI 文档](https://dart.dev/interop/c-interop) 和 [Rust 官方 FFI 文档](https://doc.rust-lang.org/stable/nomicon/ffi.html)。当前网页文档可能对应较新 Dart，构建方式必须在保留的 3.11.0 工具链验证，不因文档示例升级 SDK。

## 为什么迁移不能直接承诺减少几百 MiB

已有工作集和堆引用图的完整证据在 `docs/memory_breakdown_20261011.md`。其中地图原始数据与投影并集约 16.64 MiB、NIED 指定数据引用约 7.52 MiB、当前雷达图 RGBA 像素量约 23.76 MiB；它们口径不同且可能共享，不能相加当作全部内存。DLL/驱动/系统/输入法驻留页一次分类约 95.07 MiB，迁移业务数据处理不会自动释放这些页。Profile 的 VM 诊断服务另有自身开销，不能把它当 Release 产品常驻内存。

Rust 迁移瞄准大量临时对象、帧间复制和重复业务状态；剩余引擎、字体、音频和图形私有分配仍要继续归因。原生分配同样计入进程内存，单看 Dart 堆变小不算成功。

## 接口与线程设计

采用版本化 C ABI。首个解码模块实际接口为 `native/station_core/include/rq_station_core.h` 中的 ABI 1；下列持续会话接口仍为后续阶段的设计草案：

- `rq_abi_version`：握手检查版本与结构大小。
- `rq_session_create / rq_session_destroy`：按数据源建立有序会话，显式释放所有目录、历史、结果和线程资源。
- `rq_session_set_catalogue`：站号 UTF-8 字节表、原始经纬度 Float64、像素位置及配置一次批量加载；目录版本改变时替换，不能每帧重新构建。
- `rq_session_process_frame`：输入原始压缩字节或原始数值帧，附上来源、序号、观测时间、接收时间、有效性标记。时间用 Int64 微秒；保留原值、原顺序与缺测，不用显示用峰值代替原始观测。
- `rq_result_acquire / rq_result_release`：输出连续数值数组、有效性掩码、事件/质量记录及版本；Dart 读取完成后释放，禁止已释放内存的 TypedData 继续被 UI 使用。
- `rq_session_memory_stats / rq_session_reset`：记录当前/峰值分配、保留容量、排队数量，重连/回放/销毁按原规则重置。

FFI 调用放在持续工作 isolate 中，长计算不占 UI isolate。输入缓冲由调用者持有到调用结束，Rust 不在返回后悬挂引用；需要排队时显式转移或复制一次并记录字节量。结果采用有限生命周期的批量缓冲；不能逐站 JSON 往返，也不能把整个业务对象图同时维护在 Rust 和 Dart 两边。

观测按顺序处理，不丢弃中间帧以换取低占用。处理能力不足时记录队列和延迟并判定验收失败；只有展示输出允许合并刷新，检出输入不合并。Rust panic/错误须在 ABI 边界转成明确状态，不能跨 FFI 展开；平台 UI/语音调用仍回到现有 Dart 主 isolate。

## 原始数据与等价性验收

使用已保存的奈良 51 帧 GIF / 1634 站、其他多图层原始采样、P-Alert 787 站原始目录和 12 份原始响应、S-net 原始录像，以及现有缺测/乱序/重置回归。为原文件建立 SHA-256 清单，运行前后核验。不得修改时间、震度、震级、报数或图像再送入对照。

解码像素和离散输出必须一致；Float64 字段先做逐位比较，若底层数学库造成差异，须定位具体原始帧和字段并单独审查，不能先设置宽松容差掩盖偏差。真实样本覆盖不到的边界由已有受控单元测试补充，明确区分它与真实数据性能结果。

以冻结的当前 Dart 实现为参考。Windows 先验证独立 DLL + Dart FFI；之后 Android 同样重放。验证阶段可同时跑两套实现比较输出，性能验收时必须各自单独运行，避免双算污染结果。切换正式实现前保留可恢复源码和构建记录，正式运行不再长期执行两套核心。

## 收益门槛和退出条件

下列是提议的工程验收门槛，不是已测收益：

1. 原始数据、检出/事件/过滤/语音及 UI 结果保持一致，连续运行无队列积压和越界、释放后访问。
2. 被迁移模块的 CPU 批次耗时至少降低 30%，或模块保留内存至少降低 20%；同时完整 Release RSS、私有提交与帧耗时没有回退。
3. 整体迁移目标：同一原始输入、同一显示场景的 Release 稳态 RSS 中位数降低至少 20%，P95 不升高。若无法达到，报告实际可归因收益，转查原生资源/渲染架构，不能继续声称仅换语言就会解决。
4. 3 次交替顺序的冷启动测量、30 分钟持续回放及重连/关闭后资源释放通过；只有组件微基准通过不进入正式安装包。

若阶段 1 没有模块级收益就保留现实现并记录原因，不把新增 Rust 依赖直接加入产品。若阶段 1 有效而整机仍高，继续阶段 2、3；阶段 3 后仍主要是引擎/图片/插件，则改为资源生命周期或渲染层方案，不以更多业务语言迁移掩盖问题。
