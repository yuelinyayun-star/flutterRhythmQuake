# NIED 检出入口重复连接修复

本次只修复实时数据到检出的连接归属和时序。没有修改原始 GIF、测站值、KA 活跃度公式、检出人数门槛、活跃度门槛或 10.5 秒保持时间。

## 实机证据

2026-10-17 晚间运行的已安装程序仍在接收 KMONI。原始记录来自 `nied_replay_20261017_202249.json` 及同名 capture 目录。

截图时段的记录包含熊本县 KMM006、KMM005、KMMH16、KMM008、KMM009、KMMH14 的弱检出，随后在弱检出和 idle 之间反复切换。成功帧的记录顺序包含重复与回退，例如 JST `23:10:18 → 23:10:17 → 23:10:19 → 23:10:18`。不能把按时间排序后的回放等同于当时进程实际收到的顺序。

单独运行数据所有者，用截图时段 205 份未修改 KMONI GIF 输入，旧同步检出与当前原生检出都没有触发，结果一致。完整后台接入路径同样未触发。额外 40 秒实时 KMONI 独立连接接收 39 个不同时间帧，无检出、无连接错误。这些结果只证明独立连接下的行为，不代表已安装旧程序的状态。

## 查到的连接问题

Windows 地图通过 `NiedRealtimePipeline` 运行独立数据所有者。调试页的 `_ensureNiedGifMonitorRunning` 仍直接启动 UI isolate 中的旧 `LmoniImageService` 和 `NiedMonitorService`。地图又监听该旧服务的普通 stationStream，并把数据当作显式导入发送到后台所有者。打开调试页可使两个独立测站历史并存，旧连接结果进入正在运行的检出链路。

另一个问题是恢复连接时只比较最后一帧是否相等，没有阻止更旧的元数据时间进入实时处理。图像服务会将负时间差按回放处理、清空 KA 缓冲。

## 修改

- 原生所有者运行的平台，调试页只读取准备好的显示帧，不启动另一条旧 GIF 连接。
- 普通观测、准备好的显示视图、用户显式导入使用各自的广播流。后台所有者只接受显式导入流，准备好的 UI 视图不会反向进入计算。
- 实时监测恢复时拒绝重复或倒退时间。显式回放仍允许倒退，原始时间保持不变。
- 调试页异步设置读取返回后先检查页面是否仍挂载，避免退出后遗留订阅。

## 验证

40 项回归通过：包含显示流隔离、显式导入保留、元数据恢复回退拦截、原始 GIF 取样、KA 历史与空间检出、真实地震样本的完整后台检出和推算链路。

静态分析没有错误或警告；地图文件有 17 处此前已有的花括号样式提示。本次未扩大修改这些位置。

当前已安装程序不会自动加载修改后的 Dart 代码。需要使用包含本次修复的新构建，继续核验打开/关闭调试页后的实际行为。
