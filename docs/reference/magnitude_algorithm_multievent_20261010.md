# 小震震级算法：多事件标定与留一验证（算法侧提案）

核对日期：2026-10-10。性质：**用真实波形做算法标定与验证的离线实验室 + 候选算法提案**。
生产默认路径**零改动**；候选实现见 `lib/core/source_estimation/magnitude_perstation_candidate.dart`（未被引用）。

---

## 0. 为什么不是"App 回放"

此前 `tools/knet_app_reduction.py`（归约器）做的是：**把 K-NET 波形降智成 App 会看到的
GIF 输入，再回放出 App 会给出的 M**。它回答的是"App 为什么错"——**归因**，不是**改进**。

本实验室换一个方向：**把 K-NET 波形当作全保真观测（每站真实震度 I + 真实距离 R），
直接用来拟合震级算法本身，并做跨事件留一验证。** 这才是"用波形替代缺失部分"。

## 2. 发现一（结构性）：生产公式在内陆浅震**退化为常数偏移**

生产：`M = (I_q − 0.94) + 1.73·log10(D)`，`D = max(震央→最近 scratch 站距离, 20km)`。

实测 9 事件的 D：

| 事件 | 最近 scratch 站 | 距km | 钳后 D | 距离项 |
|---|---|---:|---:|---:|
| 熊本 | 益城 | 1.90 | **20.0** | 2.251 |
| 胆振東部 | 厚真 | 12.49 | **20.0** | 2.251 |
| 能登 | 珠洲 | 3.26 | **20.0** | 2.251 |
| 長野 | 諏訪 | 5.12 | **20.0** | 2.251 |
| 会津 6/24、6/27 | 檜枝岐 | 2.46 | **20.0** | 2.251 |
| 山梨 | 都留南 | 3.21 | **20.0** | 2.251 |
| 新潟 | 小木 | 38.91 | 38.9 | 2.751 |
| 福島県沖 | 原町 | 63.27 | 63.3 | 3.116 |

> **9 例中 7 例的 D 被钳到 20km 下限** → `1.73·log10(20)=2.251` 成为**常数**。
> **生产公式对内陆浅震实际是 `M = I_max + 1.311`**：距离项不参与。

**推论**：此前反复强调的"**强度-距离配对错误**"在钳位情形下**没有影响**（距离是常数，配谁都是常数）。
真正决定小震震级的，是 **`I_max → M` 这条映射本身**；而 `+1.311` 这个偏移是**错的**——
数据拟合的退化偏移是 **+1.102**（见 §3），生产**系统性偏高约 +0.36**（用全保真输入时，见 §4）。

## 3. 发现二：衰减律的系数与生产严重不符

拟合 `I = a·M + b·log10(R) + c`（操作域：`I ≥ 0.5` 且 `R ≤ 300km`，震源距）：

| 组 | 模型 | a | b | k | c | RMS | N |
|---|---|---:|---:|---:|---:|---:|---:|
| ALL | M1 | 1.264 | −3.235 | — | 1.417 | 0.748 | 1087 |
| ALL | M2 | 1.253 | −2.301 | −0.00330 | 0.037 | 0.743 | 1087 |
| **小震(M<5)** | M1 | **1.433** | **−3.373** | — | **0.912** | 0.557 | 184 |
| 小震(M<5) | M2 | 1.434 | −3.412 | 0.00022 | 0.960 | 0.557 | 184 |
| 大震(M≥5) | M1 | 0.704 | −3.272 | — | 5.577 | 0.757 | 903 |
| 大震(M≥5) | M2 | 0.732 | −2.402 | −0.00276 | 3.959 | 0.755 | 903 |
| — | **生产隐含** | **1.000** | **−1.730** | 0 | **0.940** | — | — |

`M2` 含非弹性项 `k·R`。**距离斜率 b ≈ −3.2 ~ −3.4，是生产 −1.73 的近两倍。**

**方法学校验**（这一步必须做，否则结论不可信）：

- 池化拟合的 M 斜率会被"跨事件共线性"污染：`corr(M, 事件平均 log10R) = 0.974`。
- 改用**事件内回归**（M 固定，纯距离效应）复核，操作域内站数加权斜率 `b ≈ −3.85`（震源距）/ `−3.11`（震央距）；
  全量范围 `≈ −4.1`。**即使只看可感区，斜率仍远陡于 −1.73**，说明这不是池化伪影。
- 保留的疑点：该经验斜率**比 JMA 物理式**（由 `I=2.68+1.72log10PGV` 与 Si–Midorikawa 距离衰减推得，
  约 −2.1/十倍距离）**更陡**。可能来自**场地放大差异**（近站软土放大、远站基岩），
  属真实数据特征，本文按**经验拟合**使用，不主张其为物理真值。

大震组 a 只有 0.70：M7+ 近场强度**饱和**（能登实测 maxI 6.69、熊本 6.26、胆振 6.45），
线性模型在大震端被压平。**故小震目标域应由小震组独立标定。**

## 4. 发现三：逐站反演 + 稳健合并显著优于生产（留一验证）

候选算法（JMA 思路：**每站用自身震源距反演 M，再稳健合并**）：

```
对每个站 i（I_i ≥ 0.5，R_i ≤ 300km）:
    M_i = ( I_i − b·log10(max(R_i, 20)) − k·R_i − c ) / a
稳健合并: 中位数 / MAD 剔异常(3×1.4826×MAD) 后均值；站数不足→最强站单站
```

**留一交叉验证**（每次留 1 事件，系数由其余事件拟合）：

| 算法 | 全 9 事件 bias / RMS | **仅小震(M<5, N=5)** bias / RMS |
|---|---:|---:|
| A_prod 生产复刻 | +0.360 / 0.500 | +0.257 / 0.449 |
| M = I_maxq + 1.102（退化模型） | 0.000 / 0.479 | −0.052 / 0.536 |
| 逐站反演 M1（中位数） | −0.087 / 0.431 | −0.176 / 0.298 |
| 逐站反演 M2（中位数） | −0.076 / 0.426 | −0.143 / 0.269 |
| **逐站反演 M2 + MAD 稳健合并** | **−0.051 / 0.405** | **−0.099 / 0.243** |
| **JMA 式最小二乘 M2** | **−0.047 / 0.396** | **−0.088 / 0.223** |

> **在项目的小震目标域上：RMS 从 0.449 → 0.223（−50%），bias 从 +0.257 → −0.088。**

逐事件（小震组，留一残差）：

| 事件 | Mj | 生产 | 逐站 M2 稳健 | JMA式 M2 |
|---|---:|---:|---:|---:|
| 新潟 | 4.6 | −0.29 | −0.15 | −0.15 |
| 長野 | 3.1 | +0.04 | +0.14 | +0.17 |
| 会津 6/24 | 3.0 | **+0.81** | **−0.20** | **−0.18** |
| 山梨 | 3.4 | +0.41 | +0.02 | +0.11 |
| 会津 6/27 | 3.5 | +0.31 | −0.53 | −0.39 |

改善主要来自修掉了会津两例的系统性偏高；会津 6/27 出现 −0.53 的过冲，
提示**弱震少站时方差仍大**（该例仅 26 站、最强站 FKS029 仅 I=2.68）。

## 5. 推荐算法（可直接实现）

**系数（默认，小震目标域）**：

```
a = 1.4334,  b = −3.3730,  k = 0,  c = 0.9120     (M1 形式，5 事件标定)
```

**公式**：

```
M_i = ( I_i − b·log10(max(R_i, 20)) − c ) / a     ,  R_i = sqrt(震央距² + 深度²)
M   = robustMean( {M_i} ; MAD-3 剔异常 )
```

**兜底**：`I_i < 0.5` 或站数 < 2 时，退化为"最强站单站反演"，并在诊断里显式标注。

**代码**：`lib/core/source_estimation/magnitude_perstation_candidate.dart`
（`MagnitudePerStationCandidate.estimate(...)`，含 `kMagnitudeCalibSmallM1V1` / `kMagnitudeCalibAllM1V1`）。

**接入点（App 侧）**：`source_estimator.dart:1518-1531` 目前只取
`magnitudeIntensityState.maximumFor(codes)`（**只要最大值**）。改为逐站需要：

1. 在 `SrevKaizouMagnitudeIntensityState` 暴露**逐站持留值**访问器（现仅 `maximumFor`）。
2. 用 `NiedStationDb.stations`（**已含每站 lat/lng**）把站码映射到坐标，
   与已发布的震源（lat/lon/depth）算 `R_i`。
3. 调 `MagnitudePerStationCandidate.estimate(...)`。

> **本文件为候选/影子实现，不修改生产默认路径。** 是否切换、是否做成开关或影子对比，属产品决策。

## 6. 边界、风险与后续

- 样本仅 **9 事件**（小震 5 事件 / 184 站），`a` 在小震组**约束较弱**（M 动态范围仅 1.6）。结论方向可信（留一验证成立），但**系数精度有限**；建议每新增若干事件即重跑标定。
- 经验距离斜率（≈−3.3）**比 JMA 物理式更陡**，成因（场地效应 / 强度下限 / 函数形式）**未定论**，按经验使用。
- 大震端（M≥5）**不能**套用小震系数（近场饱和），已单列 `kMagnitudeCalibAllM1V1` 兜底；大震专用模型需另标。
- 未评估：`k·R` 非弹性项在小样本上的稳定性（小震组 k≈0，可暂置 0）。
- 样本未并入冻结统计；生产算法/fixture/扫描表**零改动**。

## 11. 更新（2026-10-10 深夜）：把 kumamoto 的 −0.79 分解到 52 事件语料

**背景**：用户提供 P2PQuake 客户端真值 —— kumamoto 10-10 19:00 官方 **M2.6** vs 本管线重放 **1.81**（**−0.79**）。
把这一分解推广到全语料，检验"小震是不是普遍贴着量化底"。
脚本 `tmp/knet_mag_lab/floor_diagnose.py` → `floor_diagnose.txt` / `.json`。

**记号**：`Imax`=事件内最大**连续**計測震度；`Iqmax`=最大**量化**值（生产真正用的）；
`k_e = Mj − Iqmax`（生产式 `M=Iqmax+k` 成立时"需要的常数"）；`resid = prod − Mj = 1.311 − k_e`。

**分档汇总（按 Imax 的 JMA 震度档）**

| 档 | 事件数 | 平均 Mj | 平均 Imax | 平均 k_e | 平均 resid |
|---|---:|---:|---:|---:|---:|
| 1（0.5–1.5） | 3 | 3.73 | 1.15 | 2.68 | **−1.10** |
| 2（1.5–2.5） | 13 | 4.12 | 1.93 | 2.34 | **−0.69** |
| 3（2.5–3.5） | 23 | 4.26 | 2.97 | 1.46 | +0.01 |
| 4（3.5–4.5） | 8 | 5.53 | 4.15 | 1.57 | +0.11 |
| ≥5弱 | 5 | 6.90 | 6.14 | 0.90 | +0.58 |

**结论**

1. 生产误差**不是震级 M 的函数，而是「观测震度档」的函数**：档越高越准，档越低越低估。
   `corr(Imax, k_e) = −0.50`；`corr(Mj, k_e) = +0.11`（震度驱动 >> 震级驱动）。
2. 生产固定的 `+1.311` **只在震度3档附近成立**（档3 k_e=1.46 ≈ 1.311）；
   震度2档 k_e≈2.34（偏低 −0.69）、震度1档 k_e≈2.68（偏低 −1.10）
   ⇒ **"常数"根本不常数，它随观测震度下移而增大**。
3. **1/6 网格量化不是主因**：事件级 `Imax − Iqmax` 平均仅 **0.15**（最大 0.33，且量化值落在 1/6 网格上）
   ⇒ 量化只贡献 ~0.15 级，远小于档1/档2 的 −0.69 ~ −1.10。**主因是"线性常数形式在低震度失效"**。
4. kumamoto 实测点（`k_e=2.10`、`resid=−0.79`）**落在档1与档2之间**，与趋势吻合，**不是离群点**。

**语料边界（重要）**：全语料 `Imax` 下限 = **1.05（震度1档）**，仅 3 例在震度1档；
kumamoto 的 App 侧 `Iqmax≈0.50` **低于语料下限**（真·触底）。
⇒ 语料能证实"低震度档 ⇒ 生产低估"的方向与量级，但**"震度0–1、Iqmax≈0.5"这段最极端的运行区只有那 1 个实盘点**。

**机制 B —— 强度-距离错配**

## §21 源估展示改为 JMA 式「预估震度」（检出 → 预估）

> 用户裁定：源估事件算法/UI 现显示**检出震度**，改为 JMA 式**预估震度**；
> 口径 = **全网最大**（JMA 业务口径）；缺参时与统一 UI 的「无震度」一致；**完全替换**检出值。
> 落地日期 2026-10-14。

### 21.1 JMA 依据

业务链（気象庁 2024 参考資料 / 司・翠川1999 / 松岡・翠川1994 / 翠川等1999）：

```
Mj → Mw = Mj − 0.171
   → log10(PGV600) = 0.58 Mw + 0.0038 D − 1.29 − log10(x + 0.0028·10^(0.5Mw)) − 0.002 x
   → 地表 PGV = ARV × 换算 × PGV600
   → I = 2.68 + 1.72 log10(PGV)
```

`x` 为源到目标点最短距离（有限源以「震源 + 半断层长」近似，业务下限 3km）；深度 >150km 业务不预测震度。

### 21.2 现状（改前）

`lib/widgets/ui/alert_module.dart`：`_sourceEstimationUnifiedEventV2` 的 `maxIntensity` 来自
`_sourceEstimatedJmaIndex`（读 `nied_max_jma_shindo_index` / kotoho7 `js_map_max_shindo_index` /
palert `palert_max_cwa_intensity_index`）⇒ **观测/检出值**；徽章 `_buildSourceEstimationBadge` 标签为 `检出震度`。

### 21.3 关键发现：机制已在生产，只是源估徽章没用它

- `IntensityCalculator.calcJmaShindo`（`lib/core/intensity_calculator.dart:141`）= **完整 JMA 链**（断层长 + 3km 下限 + PGV600 + ×1.307 + ×ARV + I-PGV）。
- `IntensityCalculator.calcMaxJmaShindo`（L287）= JMA 式**最大预测震度**（对 `JmaSeisIntLoc` 全站取 max）。
- **生产既有口径**：地图层 `intensity_fill_layer.dart` 与 `quake_provider.dart` 均用 `calcJmaShindo` + `JmaSeisIntLoc.arv`。
- `JmaStyleIntensityPredictor`（`static_intensity_attenuation.dart`）是另一条（0.90→PGV700 基线、距离下限 1km、无断层长），**仅实验、未接生产**。

### 21.8 核查更正（2026-10-14）：源估事件**没有接语音**，语音改动已撤回

**触发**：用户质疑「我们没接过语音吧」。核查后确认**属实**，§21.4 原列对 `alert_voice_helper.dart` 的改动是**不可达死代码**，已撤回。

**证据链（源估事件从不进播报路径）**

| 事实 | 位置 |
|---|---|
| 全部 TTS 调用（`speakEew` / `speakEvent` / 倒计时 / 到达）只作用于 `QuakeProvider._unifiedEvents` | `quake_provider.dart` 4723 / 4731 / 4993 / 6617 / 4980 / 4982 |
