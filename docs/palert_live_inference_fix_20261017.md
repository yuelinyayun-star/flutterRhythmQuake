# P-Alert 实时推算与冷启动整改（2026-10-17）

## 已确认的问题

P-Alert 的 HYP 搜索与评分已使用既有原生核心，但邻站构建仍在 Dart 中执行。787 站逐站排序时，比较器反复调用 Vincenty 距离计算，冷启动实测约 4 秒，独立 worker 首次请求约 4.5 秒。

地图原先在检出结束、格子清空或显示过期时调用 worker.reset，连同原始拾取预热和固定几何一起销毁。下一帧重新启动，既重新付出邻站构建成本，也丢失此前已收到的七至八个实际样本；这可使随后已检出的事件缺少推算所需预热。实时输出仍受六秒接收新鲜度检查约束，不能通过延长过期窗口掩盖耗时。

这次记录在独立旧 worker 中能够产生结果，因此不能把截图直接解释为“P-Alert 完全没有接入”。当前配置中 `show_estimated_epicenter=true`、`hide_grid_on_eew=false`，本轮没有修改显示开关、推算门槛或震级公式。

## 修改

- Windows 邻站计算迁入 Rust，保留 WGS84 Vincenty、整米取整、四方向各三站以及 Dart 3.11 同距离排序顺序。实测全部 787 个邻站列表与原实现逐项一致。
- 增加 `PAlertSourceDriver` 管理实时会话、过期与发布；地图只传递输入、订阅显示和请求镜头刷新。
- 检出/显示清空只清空可见结果，保留原始预热与固定几何。关闭来源、关闭推算显示、释放页面或 worker 错误时释放会话；实际源时间间隔超过六秒仍由拾取器清空无效历史。generation 继续拦截过期任务结果。
- 新 DLL 尚未加载的旧 Windows 进程沿用原实现，完整重启新版程序后使用新内核。没有给失败计算补假坐标、伪造触发或引用官方震源作为推算输入。

修改前当前工作区源码备份及完整审计原文保存在 `tmp/palert-audit-20261017/before/` 与该审计目录。没有还原其他已有修改。

## 占用边界

审计期间读取的是仍运行旧 DLL 的 Debug 进程。VM 的多个 isolate 属于同一 isolate group，`getMemoryUsage` 返回相同组的共享堆数字，不能把各次返回值当作独立 isolate 的内存相加。本轮未取得截图中活跃推算阶段的同条件整机前后对照，不能据此声称已解决全部高占用。

新的本地程序位于 `build/windows/x64/runner/Profile/`；`rq_station_core.dll` SHA-256 为 `85E85E9CE8249D2DE2BF54D8A6C570C5A4577487982D21FC86523E98396B3010`。完整重启该目录中的程序后才会加载新原生内核。
