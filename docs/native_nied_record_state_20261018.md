# NIED 逐站事件状态与历史查询迁移（2026-10-18）

## 本轮完成

- Windows 常驻推算 worker 的 NIED 事件新增一个 Rust `NativeStationRecordOwner`；一个活动事件对应一个原生会话，逐帧批处理原始样本。
- 逐站是否形成有效记录、idle/rising/triggered/strong/ended 状态、记录计数、首次显式上升／触发区间、结束与再次触发处理改由 Rust 维护。
- 有限数值筛选、当前值与事件峰值、独立 PGA／PGV／PGD 筛选、事件物理峰值及其触发时间窗口改由 Rust 维护。原始观测对象仍作为输出元数据引用，不重建或修改源报文。
- 输入为原始字段的数值／时间／原始浮点位表示；输出为现有记录视图需要的状态。Rust 输出字段变化位图，Dart 不再重复更新未变化字段。
- NIED 历史的 1／4／9 秒变化量、即时变化、三槽快速上升能量判断、HYP 预触发缓存查询可直接读取 Rust 历史窗口，无需先导出窗口到 Dart。
- 事件结束、切换和 reset 均销毁原生事件会话及桥接缓冲。已经开始的旧事件在启用配置时保持其原有 owner，下一事件使用新 owner，避免丢失已有证据。

## 仍在 Dart 的部分

- driver 从测站对象构建样本、质量标记和物理观测元数据；桥接层仍进行字段封装和原始元数据绑定。
- tracker 的历史追加前时间校正、质量标记集合复用／合并、元数据保留与通用事件编排。
- NIED 分簇／HYP 会话生命周期、输入快照整理、部分估算签名和诊断结果构建。
- 完整历史窗口在按需传输及释放时的快照整理。
