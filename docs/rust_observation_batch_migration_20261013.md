# Windows 观测追加批量通路（2026-10-13）

本轮将测站记录里的原生观测追加从逐站跨 FFI 改为每帧批量提交。原数值窗口此前已经在 Rust，这次迁入的是批量调度；测站记录的其余标量字段、质量标记、物理元数据、震源发布、UI 和语音仍由现有 Dart 逻辑处理。不能将这一步称为完整测站记录状态迁移完成。SDK 保持 Flutter 3.41.1 / Dart 3.11，没有新增 Cargo 或 Dart 依赖。

## 备份与接口

源码备份 `D:/flutterApp/flutter-observation-batch-migration/20261013-121519/before-observation-batch.zip`，2,043 个文件、26,402,814 字节，SHA-256 `8b79108839a4055f2882d535d70a4a5544b25c4d4e6aba93bd11f35d30111f3f`；ZIP 已逐文件核验。保留原有脏工作区，没有 git checkout 或清理。基线冻结自上一轮输入复用版本的已核验 Profile 程序，不能重复计算前几轮收益。

新增独立观测批量 ABI 1，单行输入为原始七个 64 位字加 cutoff，结果为 status、length、oldestMetadataId、capacity。Rust 按输入顺序调用原窗口内核；同一 handle 重复出现也顺序处理，不同时产生多个可变借用。第一条失败时停止后续行，后续 status 为 6，不隐式重试或回滚已接受的前缀。批量 ABI 单次上限 100,000 行，Dart 调用方每批最多 2,048 行。

调用方三个缓冲容量共 212,992 字节（Windows x64），不包含 Dart 视图和引用列表；作用域结束显式释放。每个缓冲仅建立一次类型视图，后续追加复用。历史读取、clear、dispose 是同步提交屏障；正常退出和作用域异常退出均提交此前已接受的观测。句柄和临时缓冲不进入 isolate 消息，返回的旧窗口快照仍独立拥有数据。

Dart 保留原时间检查、电脑当地时间与 UTC 标志、Float64 原始位、质量标记以及物理观测语义。待提交的 latest 仍按原规则可读，负 retention 和日期越界时先追加再抛错的行为也保持一致。元数据确认按每条已提交行裁剪，避免重复 handle 的后续元数据被前一行错误清除。Rust 没有调用 Dart 回调；确认接口仅在 FFI 返回后的 Dart 侧执行。

## 原始数据与对照

使用未经修改的奈良 51 帧 GIF、1,634 个测站，共 83,334 条输入、40 次推算。原始输入哈希前后相同。三轮交替内存测量及三轮交替耗时测量，共 12 次独立进程，最终测量期间未同时编译或运行测试。首轮全部业务输出逐字段一致，仅 `search_elapsed_ms` 有 32 处计时差异。

实际追加观测 65,360 行，前后逻辑行数不变，跨语言追加调用从 65,360 次变为 40 次；这是内部诊断计数，不是地震报数。HYP 均为 1,066 次评分、40 次搜索、766 次测距和 300 次精确复用。关闭后的观测会话归零；Rust 当前分配均为 5,421,368 字节，原生峰值均为 5,584,351 字节。

该场景保留全部回放输入并包含 Profile VM 服务，共享 isolate group 的堆只计一次。它不能替代完整 APP 的 Release 稳态验收。当前开发代码保留这一小步，尚未达到或证明迁移计划中独立模块 30% 耗时／20% 保留内存门槛；未制作新安装包，也没有替换用户运行中的 APP。

首版每次追加都会建立一个覆盖整个缓冲容量的类型视图，完整 12 次测量的工作线程中位耗时反而增加 4.01%，往返增加 6.87%。该版程序、完整结果和源码哈希保存在 `attempt-per-row-views`，不能当成收益。最终版复用类型视图并重新测满 12 次，未混用前一次的性能结果。
