# 测站历史归档迁移（2026-10-14）

本次保持 Flutter 3.41.1，将 Windows 的测站历史归档索引、结构去重、JSON 输出与 gzip 压缩迁入 Rust。测站快照构造同时去掉一层临时 Map 复制。测量前备份为 `D:/flutterApp/flutter-station-archive-migration/20261014-101504/before-station-archive.zip`，SHA-256 为 `5361a5a441de180c92c8bae09c074d45068b86571dded4cf228ad6e763484004`。

## 数据与执行链

`EewHistoryStore._saveSeparate` 保留原来的分批后台 isolate 写入；Windows 在这个 isolate 内把原值打包送入 Rust，Rust 生成 `station-json-table-v1` 表并压缩，Dart 仅包装原有 `rq-gzip-json-v1:` base64 信封。读取协议、按需加载、报文归属与历史回放接口保持兼容。非 Windows 平台使用现有 Dart 实现。原生模块错误会报告失败，不吞掉错误后暗中改用另一套数据。

跨边界二进制区分整数、原始 float64 位、布尔、空值、UTF-16 字符串、列表与有序 Map。重复字符串和已完成的同一容器使用引用；Rust 再以精确类型和值去重节点。数据不经过降精度、抽样或字段改名。UTF-16 中日韩文本、代理对和独立代理单元均保留。

调用结束后销毁原生归档 owner，Dart 输入、状态、输出缓冲也在 finally 释放。限额为输入/输出各 128 MiB、两百万不同节点、递归深度 512、十万帧。gzip 使用 zlib-rs 的级别 3，仅改变存储字节，不改变展开内容。

`snapshotSourcePayload` 继续对可变 Map/列表创建不可变副本；已符合字符串键类型的 Map 直接进入原来的递归快照步骤，不先做一次 `Map.from`。这不是把实时可变对象直接共享给历史。

## 组件验证

18 项 Rust 测试通过；Dart 的原生 codec 测试实际加载 DLL，没有跳过。检查10,000 组随机有限双精度数及极值的位级往返、整数/双精度区分、正负零、中文日文和 UTF-16 边界、空归档、非法输入及 owner 释放。另从保存的原始 NIED、CWA、P-Alert 归档各选三块，比较所有字段、键顺序、类型和浮点位；压缩与未压缩原生路径均经现有读取器验证。

历史原文、存储、延迟加载、归档优化与估计显示测试 36 项通过、1 项因缺少可选旧夹具跳过；随后原生归档和测站快照/到期测试 8 项通过。新模块、调用方和快照代码静态分析无问题。2535 个原始采集文件 SHA-256 重新核验，差异为零。

组件基准使用原事件修复后归档的 71 块、257 帧，AOT 编译，预热后交替执行五轮。计时包括 Dart 侧打包、FFI、Rust 索引与 JSON、压缩和 base64，没有只计算 Rust 函数。原 Dart 路径中位数 6039.414 ms，迁移后 5009.318 ms，减少 17.05%。存储长度 18742100 → 17330024 字节，减少 7.53%。这是该组件的收益，不等于完整 APP 的 CPU 降幅。

第一版二进制桥重复遍历共享容器，测量反而更慢，因此未采用；加入完成容器引用后重新测量。gzip 级别 1 的初版输出变大，最终选用经原文往返验证的级别 3。中间测量日志保留，最终组件证据为 `component-aot4.json`。

## 完整 APP 验证

同一事件的 288 帧原始 GIF 和 4 报 EEW 全部回放；49 份非空推算结果逐字段相同，4 报完整报文相同，原始文件 2535 份 SHA-256 差异为零。未记录到 Flutter 渲染异常。新归档模块实际调用 67 次，结束时归档 owner 数为零，Rust 常驻回到原来的 3515776 字节。

真实时间调度下，归档的派生快照计数为 257 和 256，分块数为 71 和 67；原始 GIF 输入数量相同，原有到期 16ms 合并和异步保存会受执行时序影响。完整 APP 的小幅 CPU 变化不作为严格单组件加速倍数；上面的组件基准才使用完全相同的 71 块、257 帧作五轮交替比较。

为了隔离归档改动，验证项目沿用上一轮完整 APP 的 Dart KA 链和其他源码，只替换本次模块及快照复制代码；根工程中此前另一个待测的 KA 迁移未混入本次整机对照。该结果也不是当前安装版的实时占用。候选程序仅用于隔离验证，没有覆盖正在使用的安装版；验证结束后已关闭自己的候选进程。
