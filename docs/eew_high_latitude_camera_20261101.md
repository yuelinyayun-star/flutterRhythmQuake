# 扬马延 EEW 视角偏移修复与验证

## 范围与原因证据

本轮只修 EEW 波圈视角拟合后的震中偏移，不改 GQ 报文适配、震度、坐标、波圈尺寸、配色、缩放门限、跟随释放时长、轮播或情报填色视角。

截图对应扬马延事件 `fa88fe64-3539-4150-8a44-9f3466c679bb` 第4报。由本机历史逐字节取得报文，含实际 Java 对象流解码数据，SHA256 固定在回归测试中。原始震中为北纬70.93610382080078°、西经6.487203121185303°。

调用链：`QuakeMapView._applyCameraPolicy` 的 EEW 波圈入口 → `MapStateProvider.smartMoveToEvents` → `_fitViewToViewport` → `CameraFit.bounds`。EEW 不经过情报 `informationFillBounds`，本轮没有修改 `QuakeMapView` 生产文件。

`git show fb9bd1a -- lib/providers/map_state_provider.dart` 明确显示，当时新增波圈视口拟合，并将原来的 `final center = view.center` 改成 `final center = fittedCamera?.center ?? view.center`。该逻辑在当前 HEAD `ac247d8` 和本轮修复前一致；上轮情报填色修改没有改这一段。不能把本问题归因于上轮情报填色改动。

地理纬度上下等距的边框，在墨卡托投影上并不围绕震中对称。此事件处于高纬度，拟合边框得到北纬75.11648652793163°的地图中心，替换了原震中中心。在1584×796的实际地图投影回归中，震中下移231.5710722962741px。此问题原有测试未覆盖；仅检查原有普通纬度和缩放效果不足以保证中心约束。

## 修改

- 波圈拟合继续提供原有缩放值，中心恢复为原有震中组中心，不采用边框的投影中点。
- 相关目标选择和原有离散缩放策略切到 Rust `eventCameraTarget`，Windows 生产由 FFI 实际调用；没有静默回退到 Dart。Flutter 继续负责投影、已有 `CameraFit` 和动画。
- 多震中原有聚合中心、远距离首次飞行、缩放上下限、波圈拟合尺寸和10秒释放门保持原样。
- `smartMoveToPoints` 及其填色、特殊情报固定锚点路径未改。

## 影响边界

- 已证实：该第4报在波圈跟随时中心错误，桌面和手机均复现。
- 共享入口的潜在影响：其他正在跟随波圈的 EEW 也会采用投影边框中心；偏差随纬度和波圈范围增大。不能据此声称其他 GQ 事件已经发生同样严重错误。
- 无波圈拟合时原来已经采用震中组中心，此分支输出保持一致；原有离散缩放分段在 Rust 单测中逐档对照。
- 情报填色、各特殊情报、共享视角不由这处 `fittedCamera.center` 决定。相关回归见验证日志。
