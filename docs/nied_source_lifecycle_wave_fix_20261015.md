# NIED 推算结束与波圈走时修复

## 已确认的代码问题

地图的估计签名包含 `event.updatedAt`，因此每次接收帧都会更新签名。
参考推算会复用未变动簇的估计，其中 `wave_elapsed_s` 仍是上一次算法计算时的值。
原地图却在每次签名改变时把秒表归零并重新使用该旧值，波圈因此在两次接收之间长大，收到下一帧又缩回。

震源簇原先使用 `inactiveStations` 判定结束。该列表是评分输入，驱动只收集
KA 等级存在、低于 6、无 activity 且非活动的测站。已退出活动但等级较高或缺测的历史成员不在该列表中；
只要其他区域还有活动测站、全网不为空，旧簇就可能一直无法满足“全部不活动”。
这是代码路径的确认，尚未完整复现截图时刻的运行现场。

## 修改

- 走时锚点独立于事件刷新时间，以真实算法走时和发震时间是否变化判断新样本。
  缓存样本不会重置秒表，多震源各自持有锚点；事件结束、切换时释放锚点。
- 簇结束依据当前 KA 活动成员，连续 10 次更新无本簇活动成员后结束。
  评分仍使用原来的低等级测站集合，历史成员、搜索、评分、观测值不变。
- 保留现有波圈颜色、样式、半径算法以及 300 秒隐藏规则。
- GQ 按用户后续要求停止排查，没有修改其代码。Android 构建已取消。

## 验证

- 波圈时钟、半径显示、震源估计与驱动共 43 项测试通过。
  覆盖缓存样本连续 180 秒推进、独立多震源锚点、发震时间修订、清空，以及其他区域仍活动时旧簇在第 10 次确认结束。
- 本地保存的奈良原始 GIF 51 帧、每帧 1634 站完成回归，40 帧非空推算；
  worker 与串行驱动的事件及震源要素一致。未改写原始 GIF。
  该回归用于链路正确性，不能代替完整实时 APP 的帧率、CPU 或 GPU 对照。
- 定向分析无 error / warning；地图文件仍有 13 项已有的单行 if 风格提示。
