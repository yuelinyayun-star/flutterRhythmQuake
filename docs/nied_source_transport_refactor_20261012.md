## 实现

`NiedSourceEstimationWorker` 原来每帧创建完整 `NiedStation.detachedSnapshot`，复制目录、可变观测和 KA 等级历史。推算 driver 不读取 KA 历史，却为它承担分配、跨线程复制及活动保持计时器的间接持有。

新增 `NiedSourceStationEncoder` / `NiedSourceStationDecoder`：

- 每个目录版本只发送一次目录；比较所有目录字段与顺序，变化或重置即重发。
- 在第一个 await 前捕获每一帧原始动态字段，不合帧、不丢帧；整数与 Float64 批量传递，观测和质量标记保留原值与顺序。
- 工作 isolate 复用自己的测站对象。每帧替换输入前取消旧帧的推算保持计时器，目录更换及关闭时也释放；主 isolate 的计时器不动。
- KA 历史留在原计算所有者，不再发送给不读取它的推算 driver。主测站历史和已有消费者不变。
- 时间保留微秒、空值及 UTC／本地标志。每帧对相同微秒和相同表示复用 `DateTime`；两个时间表示使用独立缓存，缓存不跨帧持有。

数字数组每站 128 字节，1634 站共 209,152 字节。这仅是数字部分，目录、观测、原因和质量标记另计，不能称为完整消息大小。

首次测量发现逐站构造本地 `DateTime` 明显回退。CPU 采样定位到 Windows 时区查询，已改为帧内复用；早期回退记录保留在阶段根目录，不作为最终收益。

## 验证

原始奈良 51 帧 GIF、1634 站，83,334 条推算输入逐字段一致；文件 SHA-256 未变化。受控边界另查空值、负计数、微秒精度、同一瞬间的 UTC／本地表示、目录重排、空目录、重置、质量标记独立性和计时器释放，明确与原始地震数据重放分开。

启用已验证 Rust DLL、按原始一秒节奏回放后，后台与串行参考得到相同的 40 次震源估计；共 8 项测试通过。产品两文件与测试文件静态分析无问题。

完整检测、事件、站点记录、物理观测、历史与诊断字段的独立进程逐字段核对已通过 51 帧。唯一差异为 40 次搜索的 `search_elapsed_ms`，该字段来自 Stopwatch 的实测耗时；原值保留在输出文件与差异报告中，没有修改输入或忽略其他诊断字段。详见阶段目录 `final/verification`、`final/verification-differences.json`、`final/comparison.json`。

## 性能

同一 Windows Profile 程序，冻结旧 worker 与当前实现分别运行。每实现交替运行 3 个独立进程；性能测量期间不并行编译或测试。输入为未修改的原始 51 帧序列。

传输测量每进程预热 51 帧，再测 5 批，每批重复原始序列 5 次，共 255 帧；每实现 15 批。总耗时包含捕获、SendPort 复制、工作侧应用和回执。

| 中位耗时 | 改动前 | 改动后 | 降低 |
| --- | ---: | ---: | ---: |
| 255 帧传输与应用 | 1035.860 ms | 460.747 ms | 55.52% |
| 255 帧主 isolate 捕获 | 277.431 ms | 141.613 ms | 48.96% |
| 51 帧完整推算往返 | 18129.579 ms | 18118.863 ms | 0.06% |
| 51 帧 driver 计算 | 16668.503 ms | 16661.144 ms | 0.04% |

传输环节明显减少，完整推算几乎持平；剩余耗时主要仍在震源搜索。不能把传输降幅称为 APP 总 CPU 降幅。

组件进程为公平回放，双方都预先持有全部 51 帧完整测站快照。传输进程 RSS 中位数为 279.43 / 272.78 MiB，推算进程为 399.74 / 384.54 MiB；没有统一 GC，也不是完整 APP 的稳态内存验收，不能据此声称整体内存目标达到。

## 完整 APP 接入检查

在隔离目录构建完整 APP 的 Profile 验证入口，使用独立设置、缓存和日志目录，在线运行 90 秒，取得 17 次运行快照，未记录 Flutter 布局或框架错误。Rust KA 会话数保持 1，图像解码和 KA 调用均从 0 增长到 64。检查结束后仅关闭自己的验证进程，清理状态确认该进程已退出。

去掉前 30 秒后，平均 RSS 366.56 MiB，范围 349.38–403.36 MiB，按全部逻辑核心计 CPU 5.09%。这是在线 Profile 短时运行，与旧版本的输入和时间不同，不能据此推断内存下降。整体占用仍然较高。记录见阶段目录 `final/full-app-check/summary.json`、`baseline.json`、`cleanup.json` 与 `runtime`；构建和二进制哈希也已保存。
