## 接口与所有权

同一 DLL 新增 KA ABI 1，输入和输出各 48 字节。每帧一次批量更新，原生会话独占历史；Dart 仍保留显示字段。异常计数用有效位与有符号值分别传递，保留空值与负原值的区别。

历史列表适配器保持原始顺序、读取、赋值、插入、清空和替换。完整帧历史按需一次复制到复用的私有 FFI 缓冲，再按类型索引复制为独立、可增删的 Dart 列表。缓冲视图不交给消费者；后续更新不会修改已经发布的快照。外部导入超过 60 项的历史原样保留到下一次原有更新规则截断，不能在导入时擅自更改。

清空历史释放对应 Rust 容器；重置先分配成功再替换会话，保留列表适配器身份。关闭前将可能被外部保留的历史转成独立列表，再显式释放会话和 FFI 缓冲。退出后的测站对象仍能读取、修改并使用原 Dart 算法；不继续引用整个已关闭会话。接口错误显式抛出，不悄悄丢帧或重算。

## 性能

同一 Windows Profile 程序，原始 51 帧序列，每批重复 5 次即 255 帧。每实现 3 个独立进程，每进程 5 批，共 15 批，交替运行。每段序列按原时间重置，不修改观测、不丢帧；性能测量期间不并行编译或测试。计时包括 FFI 输入、计算及显示字段应用；另测包含完整测站快照的路径。

| 255 帧中位耗时 | 迁移前 Dart | Rust 会话 | 降低 |
| --- | ---: | ---: | ---: |
| KA 核心与输入输出 | 324.381 ms | 125.769 ms | 61.23% |
| 包含完整测站快照 | 533.615 ms | 498.945 ms | 6.50% |

不能把核心的 61.23% 当作完整后台或 APP CPU 降幅。包含快照时收益小，下一步需要减少完整对象与历史的跨线程复制。

包含快照的组件进程，GC 后 Dart 堆中位数为 30.614 / 29.884 MiB；Rust 历史请求持有 823,560 字节，FFI 缓冲 941,184 字节。把这些原生分配算回去后没有内存收益。对应 RSS 中位数 260.879 / 260.891 MiB，基本持平；这些是含 Flutter 引擎的组件验证进程，不能当作完整产品常驻内存。

早期 `component`、`component-v2` 记录包含快照回退，均未当作最终结果。CPU 采样（`cpu-snapshot-v3/cpu.json`）定位到 TypedList 通用迭代器与临时视图；改为私有缓冲、直接索引复制后才得到上述结果。只用 `final/comparison.json` 与 `summary.json` 作为本轮验收数字。
