## 2. 用户已明确的基础要求

### 2.1 一级板块

1. **地震与火山组合成一个板块。**
2. **气象组合成一个板块。**
3. **设置单独放置，使用独立页面或独立入口。**
4. 各板块互不干扰。
5. Windows 端已有的侧栏内容等，尽可能在手机端同样展示。

最新导航依据为用户 2026-09-06 草图与文字澄清：手机顶部采用独立悬浮毛玻璃栏切换页面，并突出当前选中页。此前底部导航及挤入原顶部状态栏的建议已被替代。桌面 UI 不改。

### 2.2 设计语言与复用

- **设计语言不能改变，现有界面是毛玻璃。**
- 保留半透明深色背景、模糊、细边框、现有圆角、机构配色和震度／烈度配色。
- 可以复用的内容尽可能复用，尤其是**统一 UI、地震列表**。
- 不是重新设计一套事件卡片和列表，再把原字段填进去。
- 仅对桌面侧栏等在手机上没有合适位置的内容，重新安排承载位置与布局。
- 手机适配可以调整排列、宽度、换行、间距、触控区域；不能用删字段、过度缩小文字来换取紧凑。

### 2.3 实时展示不能被改成隐藏入口

- **测站面板是需要实时展示的内容。**
- 手机可以改变测站面板 UI，可以拆成多个单元重新排列，但必须显示，不是移入菜单后才可见。
- 检出、S-Net、火山、CMT 等侧栏内容，在收到符合原条件的内容时也要展示。
- 这些内容不是只供用户主动查阅的隐藏详情。
- 展开操作用于获得更多阅读空间，不能成为第一次看见实时内容的前提。
- 设计前必须弄清每个组件的业务作用，不能把所有侧栏一概归类为“可选详情”。

### 2.4 2026-09-06 补充：先还原，再重排

## 4. “互不干扰”的建议落实方式

以下是对基础要求的设计解释，尚需随设计稿确认，不是新增数据处理规则。

### 4.1 展示与视野分离

- 地震·火山板块不混入气象跑马灯、气象预警列表及气象专用图层。
- 气象板块不混入地震测站摘要和地震专用详情。
- 各自保存地图视野、缩放、图层选择、选中目标和面板展开状态。
- 切换回来恢复各自状态，不因另一个板块更新而丢失位置。
- 气象事件的自动聚焦不改变地震板块视野，反之亦然。

### 4.2 数据链路保持原有规则

- 共用原有数据连接、事件接纳、去重、合并、过滤、过期、地图联动与通知处理。
- 不因切换页面重复建立连接、重置事件、重复播报或重新计算同一份数据。
- **隐藏板块不等于关闭数据源，也不等于停止预警接收。**
- 用户显式关闭图层／来源，与切换到另一个板块，是不同操作，不能共用同一个“关闭”行为。
- 特别注意：气象地图服务已有显式图层关闭时停止轮询的处理。页面切换时是否维持该服务及快照更新，需要单独定义，不能误触发原有图层关闭逻辑。

### 4.3 跨板块提醒待确认

- 初始建议：继续按已有设置播报与通知，提供简短可点击的跨板块提示，默认不强制切页。
- **用户尚未确认这套提醒方式。**
- EEW 是否抢占显示、是否自动切页、是否覆盖气象页面，需要单独讨论，不能在改布局时自行决定。

现有手机底部面板为“预警 / 地震列表 / 状态”，预警页中包含 `WeatherMarquee` 和 `AlertModule`。桌面右侧专门面板的构建受到 `!isPhone` 条件限制，手机尚未获得同等的展示承载。

2026-09-06 补查的原有组合与外观：

- `main_screen.dart` 桌面路径在同一个 `Positioned` 内，用 `Column` 依次放 `AlertModule`、间距和 `Expanded(EqlistPanel)`；外层并非额外的统一背景卡片。
- `AlertModule._buildCompactUnifiedCard()` 自带 `BackdropFilter`、半透明背景、按事件配色的边框与顶部条。
- `EqlistPanel` 自带筛选栏、毛玻璃列表和 `_buildCollapseButton()`；非 `embedded` 模式已有隐藏／显示及侧向收起动画。
- 当前 `embedded` 手机调用不使用这套折叠控制。不能直接把现有手机底部面板当成用户认可的目标设计，也不能声称手机已具备要求中的同组展开方式。
- 折叠方向、触控把手与展开尺寸应在保留原组合的前提下适配；“原有代码侧向收起”不等于用户指定手机必须沿同一方向。

### 5.1 测站摘要与检出详情不是同一个组件

当前 `StationDashboard` 为六个测站网展示摘要：

| 来源 | 当前显示的指标 |
| --- | --- |
| NIED | 当前最大震度 |
| S-Net | 当前最大震度 |
| KMA | 当前最大烈度 |
| SeisJS | 当前最大烈度 |
| TREM | 当前最大震度 |
| P-Alert | 当前最大震度 |

- 当前一个单元对应一个测站网的最大值摘要，**不是全国每个物理测站的一张卡**。
- 用户提到“一个一个测站显示排版”，可以据此讨论拆分摘要单元，但具体是否增加物理测站级展示仍需确认，不得直接扩大成全量测站列表。
- 指标、颜色、保持窗口、尺度转换与无数据状态沿用现有处理，不把不同尺度混成一个通用数值。
- NIED 检出详情、S-Net 排行是满足条件后的额外内容，不能拿常驻最大值摘要替代，也不能反过来用详情替代摘要。

### 5.2 当前侧栏出现条件

- NIED：`_hasFormalNiedDetect()` 要求非 `idle`，且有可用检出网格、区域或测站记录。
- S-Net：`snetTopStations` 非空才有对应侧栏。现有选取逻辑从活动有效站排序取最多五站，并要求最大站达到相应非零震度条件，不是接通 S-Net 就恒定展示排行。
- CMT／火山：由现有有效事件选择函数取得当前内容。
- 长周期／巨大地震提示：使用原有有效期判断。
- 海啸：按各来源现有活动状态判断。
- 自动弹出还受当前 `_sideInfoAutoShowBeta` 等既有设置控制。迁移时必须审查这些设置，不能把“当前代码有条件控制”误述为已经无条件自动弹出。
- 桌面当前存在多内容轮播和检出分页，周期为 5 秒。手机版是否沿用、替换或加手动切换，尚待讨论，不能无声删除。

## 6. 修订后的地震·火山布局建议

### 6.1 总体结构

**地图背景 + 常驻实时测站摘要 + 统一 UI／可展开地震列表悬浮组 + 按条件出现的专门情报面板。**

地图继续作为主体背景，各模块按原有毛玻璃设计悬浮在其上。不新增大背景容器把统一 UI 和列表包起来，不改成贴底抽屉；先还原现有组合，再确定手机坐标和展开范围。

| 区域 | 内容 | 展示要求 |
| --- | --- | --- |
| 地图左侧，顶部切换栏下方 | 实时测站摘要 | 拆成独立单元竖排，直接可见、实时更新，不需要先打开详情 |
| 地图下方的悬浮组 | 现有统一 UI 与原有地震列表 | 按手机草图保持同组，平时主要显示统一 UI，列表可拉开；不另包大面板 |
| 地图右上方，顶部切换栏下方 | 原侧栏中的检出、S-Net、火山、CMT 等 | 缩小占用、保持悬浮；满足原有条件时出现实际内容，不只显示入口或计数 |
| 顶部独立悬浮毛玻璃栏 | 监测板块及设置入口 | 切换页面，选中项加光效或其他提示；不挤进原状态栏 |

具体坐标、面板高度和上下顺序需通过下一版 HTML 的真实可视面积验证，尚未定稿。

### 6.2 实时测站区域

- 可拆成独立的紧凑毛玻璃单元，分别显示来源、指标和当前数值。
- 用户第二张草图已指定左侧单列竖排，替代先前 3 列 × 2 行建议；每个单元的宽高、间距和小屏适配需通过设计稿验证。
- 不默认做成只能看见一个来源、其余必须左右翻页才能看到的轮播条。
- 固定单元尺寸，数值从个位变两位、出现 `5弱`／`5强` 或无数据状态时，不引起布局跳动。
- 有检出等专门内容出现时，实时测站摘要仍保留。

### 6.3 统一 UI 与地震列表

- 保持原有同组组合，模块各自的背景、边框和间距保留，不用一个新抽屉替代。
- 默认以统一 UI 为主，地震列表允许收起并通过明确的把手／控件拉开；具体方向、动画和手势待讨论。
- 列表展开不替换统一 UI，也不切去另一个互斥标签；事件更新不应随意重置列表展开状态和滚动位置。
- 无活动事件时列表的默认展开状态尚待确认，不自行决定空白占位或强制展开。
- 优先复用原组件，保留现有标题、徽章、报数、机构、参数、单位和特殊状态。
- 不以“手机摘要卡”为由丢失震源调查中、取消、巨大地震等既有显示处理。
- 统一 UI 和专门面板职责不同，可以同时存在；不能因为火山／CMT 已有详情面板，就取消其原来的统一 UI 表现。
- 地震列表不是监测摘要，也不是当前事件列表，不能合并替代。
- 上述职责区分不意味着布局拆开：两个组件仍在同一个悬浮组合中。
- CMT 不因为加入手机展示而被默认塞进普通地震历史列表。沿用现有来源过滤与历史列表规则。

### 6.4 专门内容的展示规则

| 内容 | 直接展示的职责 | 进一步展开的用途 |
| --- | --- | --- |
| NIED 检出 | 原有检出／强检出分组、地区及震度信息 | 较多区域的完整阅读与分页 |
| S-Net | 原有排行与时间窗信息 | 更多阅读空间，不替代常驻最大值摘要 |

| CMT | 现有参数、机制球与类型判断 | 长字段列表、球体及参数的更大阅读空间 |

### 6.5 多内容同时出现

- 自动出现的是实际内容，不是若干“查看详情”按钮。
- 可滚动承载多个专门面板仍是待讨论选项；应先还原各原侧栏模块，保留悬浮语言，不能直接采用统一贴底抽屉。是否结合桌面原有轮播／分页也需继续讨论。
- 不能为了同时塞入全部内容而将字体缩小到不可读，也不能让内容覆盖导航或阻断地图拖动。
- 新内容到达要能被看见或明确提示；普通逐帧更新不应反复抢走阅读位置。
- 全屏阅读可作为补充模式，但默认不能要求用户先打开全屏页才能发现当前检出、火山或 CMT。
- 事件结束、失效、取消和测站恢复，按原状态更新或移除当前面板。手动收起、历史查看与过期清理之间的关系仍需确认。

## 8. 性能与实现边界

以下为实施时应验证的工程约束，不是本轮已完成的 UI 改动。

- 以真机检查内存、拖动、缩放和前后台切换，不用“功能测试通过”替代性能测量。
