# Windows NIED 测站拓扑排序迁移（2026-10-13）

本轮把拓扑构建的距离筛选和排序迁入 Rust，消除 Dart 中间距离记录和排序回调。距离、方位和邻站选择规则仍保持原实现，坐标和观测输入未经修改。Flutter 3.41.1 / Dart 3.11.0 保持不变。这是首次构建拓扑的优化，不是完整 KA 空间检出或完整测站记录状态迁移。

## 备份和热点证据

逐文件验证的源码备份：`D:/flutterApp/flutter-record-hotpath-migration/20261013-132812/before-record-hotpath.zip`。共 2,048 个文件、26,416,948 字节，SHA-256 `f453e2b57a73e095387c39cee7ccea7d87d26794d3a42bb081f401fdd31ca7fa`。保留原脏工作区，基线冻结自上一轮观测时间优化的已验证 Profile 程序，不重复计入之前的收益。

优化前的独立 CPU 诊断采样周期 1000 μs，推算 isolate 共 3,152 个样本。497 个经过拓扑构建，其中 168 个经过测距、118 个经过排序比较闭包。父子调用样本重叠，不能相加成总 CPU 比例；这是单次定位，未混入正式性能对照。完整证据位于 `cpu-diagnostic`。

## 实现边界

每次拓扑构建分配一次原始距离 Float64、原始 ID Int64 和输出序号 Uint32 缓冲，合计每站 20 字节（1,634 站为 32,680 字节），各行复用，finally 中释放。Rust 在输出序号缓冲内筛选 `distance <= 300`，按原始距离、原始 ID 排序，不保留指针或会话，不重新计算、舍入或量化距离。

原 Dart 三角函数和运算顺序保持不变，避免前期验证中已经发现的跨语言 1 ULP 差异。Dart 继续执行 30 km、孤站补 40 km、检测邻站上限和四方位补站的原规则，选择顺序一致。结果仍是原有不可变邻接快照，拓扑缓存的目录、坐标、ID 和顺序失效判断不变。

原始目录 ID 唯一时使用 Windows 原生通路。非 Windows、超过明确容量上限或目录重复 ID 时仍使用原有 Dart 实现；重复 ID 与距离完全相同的比较结果为零，保留原 Dart 排序行为以免引入新顺序。这是明确的能力边界，不隐藏 DLL 缺失或原生调用错误。

新增独立 topology-sort ABI 1，station-core ABI、已有观测/评分/搜索 ABI 和依赖版本不变。已加入 Windows CMake 依赖与 C 头文件，构建包含新符号。原生缓冲仅在本 isolate 的同步构建期间使用，输出选择复制成不可变 Dart ID/代码列表后才发布。
