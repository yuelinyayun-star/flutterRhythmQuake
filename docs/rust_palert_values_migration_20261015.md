# P-Alert 响应数值字段直接提取

## 本轮接入

上一轮完成等级计算和峰值历史的 Rust 迁移后，实时响应仍需在 Dart 中遍历两个 `dataVals` 对象，生成 PGA／PGV Map，再按测站字符串 ID 查找、打包回原生。

现在复用同一次 Rust JSON 解析的原始树，按连接时配置的测站顺序直接提取数值行，随后进入上一轮的原生等级／峰值历史。没有重复解析 JSON，也不需要在 Dart 中创建这两张数值 Map 或解码其全部测站键。原始 JSON 树的独立快照继续用于现有归档；提取不改写原始字段或数字字符串。

实现：`native/station_core/src/station_json/palert_values.rs`、`station_json_decoder_io.dart`、`palert_wire_values.dart`。接入：`palert_service.dart`、`palert_level_history.dart`。新增可选 fields ABI 1，原 station core ABI 1、station JSON ABI 2 不变；CMake 已增加新源文件依赖。其他 JSON 调用不使用该提取器。

## 语义和连接生命周期

- 布局以原 UTF-16 单元传入，中文、表情、BOM 和未配对 surrogate ID 不经过有损 UTF-8 重编码。
- 保留旧 `_asDouble` 的整数／浮点转换、数字字符串语法、Unicode trim、正负零、NaN／Infinity、无效值忽略规则。原始字段值仍独立保留；NaN 以非数语义核验，其他派生数值逐位比较。
- 重复 JSON 键采用最后一个值，包括转义后相同的键；最后值无效时不能保留前一个数值。
- 全局有效 PGA 数量包含目录外测站，保持原 `pgaVals.isEmpty` 判断；不因目录尚未适配某站而改变该判断。
- PGV 时间对齐、报文时间解析、严格新帧判断仍在原服务。旧／重复响应保留原始字段归档，但不提取数值或推进历史，没有生成假空观测。
- 目录重排重新建立字段布局，旧返回结果与原始快照不受复用缓冲、失败重建、目录变化及释放影响。
- 解析失败立即释放原生 owner 和 scratch，只保留目录用于下条有效报文重建；停止连接释放解析器及目录。
- HTTP 回调在解析前检查连接代次，await 返回后再检查代次。停止后的响应不会重新创建解析器，前一连接延迟返回的目录也不会覆盖当前原始归档。
- 非原生端使用同一接口的 Dart 字段转换；传输调度、目录字段适配、联合检出总控仍为 Dart。没有改动 UI、声音、震源公式及接收频率。

## 原始输入与验证

- 31 项 Rust 测试通过。
- 最终 Windows CMake DLL 的相关主组 121 项 Flutter 测试通过，包含其他 JSON 源、JSONP、原始字节、完整归档和源推算回归。
- 非原生组 74 项通过、11 项原生专属跳过。组间有重复，不累加独立测试数。
- HTTP 集成使用原始响应字节，验证完整测站数值和时间、旧帧拦截、重复帧不增加 native 提取计数、停止后不创建 owner、重连后不被旧目录覆盖归档。
- 原始 JSON／GeoJSON／其他 fixture 的清理前 SHA-256 清单共 203 份，全部未变。
- 静态分析无问题，Windows Profile 的 CMake `rq_station_core_build` 目标通过。

主组部分 Provider 测试仍输出既有 SQLite 未初始化诊断，但断言通过；未据此宣称完整 APP 数据库集成已验收。日志见 `build/performance/palert_values_*_20261015.log`。

## 三轮独立 AOT 对照

两边使用同一个最终 Windows CMake DLL：`F4A48ACC7B145F9C9303840FB5628319B4ECE6A4E7959AFFF54DD7C80A7905BC`。

基线为上一轮实际路径：Rust 通用 JSON → Dart `_asValueMap` → 原生等级／峰值历史。新路径：同一次 Rust JSON → Rust 字段提取 → 同一个原生等级／峰值历史。没有再次把上一轮等级迁移的收益算入本轮。

每种负载各三轮、独立进程，交替顺序，10 条完整序列预热；每轮 150 条完整序列。计时包含 JSON 解析和原始快照、字段提取／转换、目录配置、等级／历史及输出校验和，不含磁盘读样本和 HTTP 网络等待。原始快照与输入的 JSON 解码结果一致，所有轮次输出校验和一致。

| 原始输入负载 | 每轮响应／接受帧 | 上一轮路径中位 ms | 新路径中位 ms | 耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| 原始 12 条序列重复 150 次 | 1800／1800 | 1905.478 | 833.122 | 56.28% |
| 每条原始响应原样重复送入三次 | 5400／1800 | 3023.813 | 1980.526 | 34.50% |

第二组没有修改任何报文内容或源时间，属于显式重复响应负载，不代表实际上游重复率。新路径计数为 5400 次 JSON 解析、1800 次字段提取，3600 次重复响应不提取字段。结束 RSS 中位分别为 24.805 → 23.586 MiB、24.715 → 23.602 MiB；这是小型 AOT 进程的结束快照，不是 APP 稳态内存或 GC 后保留量。

工具：`tools/benchmark_palert_values.dart`、`tools/benchmark_palert_values.ps1`；完整轮次、计数、DLL 和原始样本哈希：`build/performance/palert_values_comparison_20261015.json`。

## 运行边界

当前运行的 Profile 窗口没有关闭或覆盖，仍为前一轮完整 APP 构建。本轮构建了独立原生目标并验证实际 DLL，没有重新制作 Windows 安装程序、没有编译 Android、没有修改云端。整机 CPU／GPU、UI 帧耗时与 EEW＋测站长时回放收益仍需在包含这些修改的完整 APP 中单独验收。
