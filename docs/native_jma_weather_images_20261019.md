# JMA 雷达与卫星云图整条源链迁移

Windows 默认使用原生运行链，不需要实验开关。本轮覆盖雷达与卫星云图的时间索引、图片下载直到 Flutter 图像显示；没有修改云端、其他来源或原始数据，没有构建 Android。

## 原生与 UI 的边界

`源启停命令 → rq-jma-radar / rq-jma-satellite → WinHTTP → 原始索引解析与帧选择 → 帧快照 → 瓦片视窗请求 → 原生图片下载／重试／取消 → 原编码图片 → Flutter codec / TileLayer`

Rust 持有：

- 正式上游地址、请求头、系统／环境代理路由、网络会话与超时。
- 雷达五分钟、卫星十分钟的刷新期限；雷达启动重试、手动刷新请求合并、旧会话取消。
- 原始 JSON 的解析、日期解释、产品过滤、最新帧选择、重复抑制和卫星旧帧拦截。
- 图片请求队列、最多八个并发下载、原有可重试 HTTP 状态和三次重试（500/1000/1500 ms）、活动及排队请求取消。
- 当前显示帧、网络响应及中间缓冲的生命周期。没有请求时阻塞等待命令／期限，未增加周期空转线程。

Dart 只传启停／刷新／视窗取图命令，绑定有限帧字段，维护 Flutter 图像缓存与共享消费者，再把未经修改的编码 PNG/JPG 交给 Flutter codec。没有把整个时间索引返回 Dart，也没有通过 Dart HTTP 或 RetryClient 下载这两层的图片。

`quake_map_view.dart` 的这两层已切换到 `NativeJmaTileProvider`；其他瓦片层的 provider 没有改动。源停止并清除时销毁工作线程、取消网络请求、释放原生缓冲；仅暂停而保留显示帧时，原生会话阻塞等待。重复停用命令在显示桥中不重复发送。

非 Windows 继续使用既有实现；显式 `forTest` 构造用于旧实现对照。原生路径发生错误不会转回 Dart HTTP。

## 保持现有规则

雷达的既有本地时间解释和卫星的 UTC 解释分别保留，没有在迁移中额外修改时区规则。原始 basetime、validtime、帧选择优先级、XYZ 地址、偶数雷达 zoom、卫星 zoom、透明度和图层布局保持不变。

取消的图片按 flutter_map 契约使用取消占位，并从真实图片 URL 的待加载缓存中移除，避免停用后重开继承透明缓存。失败响应保留错误，不用占位模拟成功图片。

## 验证

- 8 个相关测试文件：62 项通过；补充首帧前暂停再清除的线程释放测试后，相关 26 项再次通过，合计 63 项不同的离线测试通过，外网验证默认跳过 1 项；该外网验证另行启用后通过。
- 已归档上游原始雷达／卫星时间索引及 PNG/JPG，带来源地址与 SHA-256。原生 HTTP 输入使用这些原字节，帧时间、地址与旧实现逐项对照。
- 图片经原生请求返回后 SHA-256 与原始图片相同；真实 PNG 经 `NativeJmaTileProvider`、Flutter codec 和 RawImage 显示，尺寸 256×256，共享消费者只发一次请求。
- 核验八请求并发上限、取消活动和排队任务、500/1000 ms 重试间隔、404 终止、重复／旧帧／坏响应、超时恢复、停止后立即重启、周期刷新和停用后的无请求状态。
- 正式默认构造实际访问 JMA：两源各成功请求一个时间索引、一个瓦片，真实 PNG/JPG 均成功解码为 256×256。结束时图片排队数、活动数、图片缓冲字节和索引响应缓冲均为零，关闭后源工作线程数回到基线。
- 一并回归普通原生 HTTP、P-Alert 代理、云图开关和上一轮统一事件 owner。
- 本轮新增／修改源和图片桥文件静态分析无错误／警告（启停桥的两处语句花括号风格提示保留）；最终正常入口 Windows Profile 构建通过，78.4 秒。

本轮没有启动连接全部地震 API 的 APP，也没有测得整机 CPU／内存降幅；这两条低频源的迁移不能直接解释原来的高 CPU。原生图片与 JSON 临时缓冲释放不等于 Flutter 必须清空仍可复用的已解码图像缓存。

修改前文件与 SHA-256、测试日志、实际原生取帧记录和构建日志保存在 `tmp/jma_tile_runtime_20261019/`。

## 当前仍需继续迁移的已核实部分

- `quake_event_adapter.dart` 的多源字段解释与展示派生仍有 Dart 实现，需要按源迁走，不能把原生 JSON 解析器算成适配完成。
- `alert_voice_helper.dart`、`tts_service.dart` 及 provider 中的播报文本／队列与倒计时业务。统一事件 owner 已给效果指令，但这些上层规则尚未全部原生化。
- `usgs_shakemap_service.dart`、`usgs_dyfi_service.dart` 的产品发现、加载与产品缓存状态。
- `obs_automation_input_service.dart`、条件解释器和 runner 的输入、匹配与操作编排；是否实际常驻计算取决于启用规则与监听状态。
- 其他天气、火山、海啸服务以及后台处理分支还需要逐条核对。没有把文字命中次数当作活动热点数量。
