# Windows 历史目录存储原生迁移（2026-10-23）

本轮将 Windows APP v3 历史目录的文件事务迁至 Rust，并连接正式
`WindowsPreferencesWorker`。不变更已确定的逐报 JSON、逐帧 gzip JSON、
事件命名、目录布局及保留规则。服务器采集器在这轮没有更新。

## 所有权与数据路径

`NativeReplayHistoryFiles` 是存储 isolate 内的序列化桥。现有模型产生的
原始 JSON 字节借给 Rust 使用；Rust 不解析重写报文/帧，也不保留所有原文。

Rust `replay_files` owner 负责目录路径、文件创建/读取/删除、SHA-256、
有界 gzip 解压、重复帧检查、不可变报文检查和原子替换。写入使用流式 gzip，
不在 Dart 创建整份压缩帧再写盘。提交先 flush/sync 文件，再替换 `.pending`。
同一 owner 的操作串行执行，正常关闭在回复 Dart 前释放 owner；返回缓冲逐次释放。

读报文校验文件名中的完整 SHA-256；重复报文若已损坏则报错。旧 Dart gzip 和
新 gzip 的头部/压缩字节可能不同，所以重复帧逐块比较解压后的完整 JSON 字节，
相同则保留已有文件及修改时间。不同内容报冲突，不覆盖。单文件展开上限 128 MiB。
路径由固定目录、key 的 SHA-256 和严格验证的摘要组成，不接收报文中的文件路径。

Windows 正式链启用原生后端。原生错误向调用者报告，不在失败后切到旧实现。
非 Windows 与未指定原生库的 Flutter 测试仍使用原来的平台实现；它也是对照基线。

## 验证

- Rust 全套 140 项测试通过，包括新模块的原文、冲突、限额和提交失败测试。
- 使用新 DLL 的历史/回放组 36 项通过、1 项可选用例跳过。
- 新桥单测核对中日文路径、原文字节、数值类型、负零、跨后端读写、重复帧不改写、
  namespace 隔离、保留/删除、失败后重试、关闭后 owner/结果归零。
- 保留副本中的两个事件，6,163 帧、46 报与旧存储逐个比较完整 JSON、类型和时间，
  全部一致；预热准备为 65.267 ms。原始副本没有作为输出目录。
- Windows 个人版 Debug 构建通过（24.1 秒）；打包 DLL 再执行桥和历史控件
  18 项测试通过，与 AOT 测量所用 DLL 的 SHA-256 相同。

## 固定原始输入的 AOT 组件测量

选取真实保留帧中的 5 类来源：NIED、KMA、SeisJS、LPGM 各 3 帧，S-net 2 帧。
输入文件和完整 JSON 摘要冻结，未修改观测。每个独立 AOT 进程保存 70 个独立文件，
再执行重复保存和读取校验；两模式交替运行三轮，输出到不同的新目录。
两个模式均加载同一 DLL，以免 DLL 初始映射造成偏差。原始文件的选择不计入计时。

| 三轮中位数 | 原 Dart 文件实现 | Rust 文件 owner | 变化 |
| --- | ---: | ---: | ---: |
| 首次写入 | 710.904 ms | 662.974 ms | 少 6.74% |
| 重复保存 | 393.595 ms | 307.720 ms | 少 21.82% |
| 读取 | 402.942 ms | 379.103 ms | 少 5.92% |
| 进程峰值 RSS | 118,292,480 B | 94,953,472 B | 少 23,339,008 B（22.26 MiB） |
| 操作后 RSS | 88,633,344 B | 85,159,936 B | 少 3,473,408 B |

这是包含序列化、文件调用、压缩/解压和模型读取的组件结果，不能代替整机
FPS、CPU 或长时间常驻内存验收。RSS 包含运行时与测试输入；并非 Rust 堆大小。
各轮结束原生 owner 和结果缓冲均归零。完整记录在
`tmp/native_history_files_20261023/benchmark-summary.json`。

## 尚未迁移的职责

这轮完成的是历史目录文件后端，未宣称 Dart 已只剩 UI。事件分组、保留业务决策、
JSON 边界序列化/模型构建、ZIP 导入导出、回放时钟与推算编排仍有 Dart 实现，
须继续按照全链路后端边界迁移。其余数据源/播报/地图的剩余业务也未在本轮迁完。
没有替换用户正在运行的安装版，没有生成安装包或恢复 Android 构建。
