# 海啸预计与观测数据接入

第一阶段增加数据链路；随后按确认的窄柱方案接入地图，见末节。新增解析、单位换算、区域关联与可用性判定在 Rust `tsunami_wave_data.rs`，通过现有 station-core FFI 使用。Dart 沿用连接管理与 HTTP 工厂，负责传递结果。现有原始报文不改写。

## 数据契约

`TsunamiMessage` 新增两个可序列化字段，旧数据缺省为空：

- `officialDetail`：官方补充详情。NOAA 保留完整对象；INCOIS 原始数组保存在 `documents` 内。
- `waveData`：Rust 派生数据，含 `areaForecasts`、`stations`、`warningActive`、`expiresUtcMs`。

站点的 `forecast` 是站点预计值；`areaForecast` 是已明确关联的区域预计值，不能冒充站点预计值；`observed` 是观测值。每个读数保留原值、原单位、米制数值（有可靠单位才转换）、时间、时区、可解析的 UTC 毫秒时间、数值类型与原始状态。原始记录用 `forecastSourcePath` / `observationSourcePath` 引用，不在每个站点复制整份详情。

`maximumWaveHeight` / `maximumPositiveAmplitude` 表示截至公报时的最大观测波高／正振幅，不是当前瞬时波高。CWA `reportedWaveHeight` 和 INCOIS `reportedWaveAmplitude` 不擅自标为最大值。第一波到达时间独立保存，不冒充测量时刻。范围与“以上”等限定值保留文字，不转换为精确标量。

`mapEligible` 仅在警报生效、源数据能证明所属预报区、坐标有效时为真。没有坐标或归属不明的观测继续保存。后续地图显示还须按当前时间复核 `expiresUtcMs`，不能永久缓存生效标志。

## 各源

| 机构 | 当前接入内容 | 尚有限制 |
|---|---|---|
| JMA（现有 Jian / WHEWS / P2P） | 区域预计最大波高；提供站点数据的报文保留预计到达、满潮、第一波、最大波高及时间、限定和修订状态；沿用独立预报／观测报次合并 | P2P 不提供同等丰富的测站观测；现有 WHEWS 观测样本没有坐标，不猜坐标 |
| NMEFC | 区域预计波高、到达时间；`waterLevelMonitoring` 站点最大波高、时间、坐标 | 仅按源报文位置与预报区同名关联，不凭省名或最近距离猜区域 |
| PTWC / NTWC | 活跃公报的 `jsonUrl` 详情：295 站原始样本验证了站点预计波幅／到达、观测最大正振幅／时间、坐标、`siteSegmentID` 与活动岸段 | 无观测时间的 `0.0` 是占位，观测值为空；有有效时间的实测零保留；英尺按 0.3048 转米 |
| CWA | 现有 `warningAreas` 预计值、`stations` 观测波高／到达／状态 | 文档未明确裸数字单位及站点所属警报区；不补猜。真实已存样本无站点数组，协议结构已适配 |
| INCOIS | 活跃公报的官方 NTWC `detailUrl`；官方前端表格的 `ZONES[].ZONE` 预计波幅及 `SeaLevelObservations[].Station` 观测波幅、坐标与到达时间 | 只接已核对的 NTWC / IST 产品；站点与预报岸段无明确关联时保留未关联。真实已存信息报无观测表，观测字段用明确标注的协议测试验证，未宣称完成真实观测样本验证 |
| CAT | 沿用已有公报 | 尚无已核验的逐站预计／观测结构，不把区域文字波高捏造成验潮站读数 |

官方详情按收到的新公报请求，不新增常驻高频轮询。它们是公报更新的近实时观测，不是一分钟潮位序列，也不是从总潮位直接推导出的海啸瞬时波高。

## 更新与验证

官方详情即使在转发消息已有岸段时也读取；异步返回受连接代次及最新公报约束。旧报、解除后返回和已断开连接的请求结果不会恢复警报。同报站点补充保留已有身份，不重复触发警报。`toMap` / `fromMap` / `copyWith` 保留新增字段，旧模型入口保持原有行为。

原始样本覆盖 NOAA、JMA、NMEFC 与 INCOIS 信息报；边界条件测试明确标注为协议测试，不注入运行 APP、不改写原始样本。

字段依据：

- NOAA 原始详情：<https://www.tsunami.gov/events/PAAQ/2025/09/18/t2ssp5/1/WEAK51/PAAQ.json>
- JMA 观测信息 XML 示例：<https://www.jma.go.jp/jma/kishou/know/jishin/tsunami/kaizen/denbun_henkou_online_besshi2_2.pdf>
- INCOIS 官方页面及其 `displaybulletins.js`：<https://tsunami.incois.gov.in/TEWS/display.jsp>（2026-10-20 已保存原始脚本，`ZONES`、`SeaLevelObservations` 字段与 NTWC 的 IST 标注）
- WHEWS JMA / CWA 文档：<https://api.beecld.com/>（已保存文档与示例，真实样本与文档占位示例分开）

## 后续地图显示：圆润窄柱，灰白细边

- 沿用已确认的 40px 宽、104px 高、15px 圆角柱体，边框 `#CBD0D5`。预计值放在上方，观测值与单位在柱内，类型和地区／站点名在下方。没有悬停提示，点击查看原始时间、状态及明细。
- 警报岸线的机构颜色和闪烁保持原有逻辑；不改地图聚焦、统一 UI 卡片入口或侧栏。旧观测圆点在新水位计接入的 Windows 地图上停用，避免重复显示。尚未具备本轮原生能力的平台保留既有入口，本轮未构建 Android。
- `tsunami_gauges.rs` 在报告／几何变化时准备位置、读数、范围限定、量程和各缩放级别的分组。Dart 只选择已有缩放级别并绘制。一个报告的所有水位计共用量程，观测可高于预计，预计不是填充上限。
- JMA 区域标记锚定现有 `jp.tsunami.topo.json` 岸线上的代表点，不虚构验潮站坐标。其他机构复用当前已加载的警报几何；来源明确关联的站点在放大后展开。不能确定位置、归属或有效警报几何时不补猜；官方几何为空也不会恢复站点图标。
- 密集位置的显示分组在 Rust 中预先计算，按当前缩放选择，完整明细保留。岸线坐标转成 Flutter `LatLng` 的已有适配仍只在几何加载完成后执行，不随地图帧反复处理。
- 原值为有效零时显示 `0`；缺测显示待观测，不填充。`以上` 用等价的 `≥` 紧凑标识，原文保留在详情；范围与不明单位不转换为确定水位。长名称用省略号，长观测描述在窄柱内显示“详情”，完整内容点击可见。
- 过期计时与连接结果更新均有生命周期检查，解除后旧异步结果不会重现。水位计不新增动画时钟、持续水波、模糊滤镜或高频网络轮询。
- 新组件有真实 Flutter 渲染检查，覆盖点击不移动地图、地图缩放不重新调用后端准备、文字缩放、缺测、过期及迟到结果；原始 NOAA 与 JMA 样本通过现有原生链路核对。

## 地图尺寸及性能复核（2026-10-22）

- 原来的 108×176 是固定屏幕尺寸。地图层现按连续缩放绘制：柱体在 zoom 5 约 29px、zoom 7 约 57px，近景最多 78px；标记的投影锚点不变，裁剪和点击范围同步缩放。
- 平移复用同一标记列表；缩放复用文字和柱体组件，仅更新尺寸及绘制变换。同一计划的组件缓存随报文更新释放，准备结果仍只在报文／几何变化时请求，不增加地图动画帧上的 FFI。
- Rust 仅缓存当前一个版本日本岸线的名称与代表点，不保留整份解码岸线。聚合坐标先投影一次再按各级缩放，地区与测站建立索引，保留原来的顺序及聚合条件。三份基准原始数据的全部准备结果（包括 19 级聚合、坐标、读数、明细）前后 JSON 逐项一致。
- 对照使用同一台机器的优化版 Rust DLL、同一个 Flutter 测试进程类型，各组预热一次后采样 40 次，计时包括 FFI 编解码。这些是报文准备耗时，不是整机 CPU／GPU 或实际帧率：

| 原始数据 | 优化前中位数 | 优化后中位数 |
|---|---:|---:|
| 2025 勘察加 JMA 40 地区 | 21.313ms | 4.728ms |
| 同次 NTWC 公报，232 个展示条目 | 34.380ms | 17.059ms |
| NTWC 2025-09-18 原始 295 站样本，8 个有效展示条目 | 5.268ms | 5.428ms |

- 第三组未见下降，不将其报告为性能改善。JMA 首次准备仍需解析岸线，首次耗时 28.918ms → 27.321ms，主要改善发生在后续公报。
- 同一份 JMA 原始数据、同一视野平移 90 帧，文字组件重建 540 → 0；另验证连续缩放不重建文字、不重新准备数据，近景尺寸上限、坐标不漂移及缩放后点击。真实 Flutter 渲染对照保存在本地专项记录中。没有据此宣称整机 CPU／GPU 降幅。

## 概览地图显示密度调整（2026-10-22）

- 按反馈提高缩小时的显示密度：聚合间距改为当前缩放后的完整标记宽高加 6px，不再占用旧的 108×178px 固定间距。已有有效坐标和活动警报区归属的测站在所有缩放级别参与显示，不再等待 zoom 7；没有可定位测站的地区继续使用原岸线代表点。
- 聚合仍在 Rust 收到公报时一次准备，沿用地图帧复用组件的机制。原始读数、有效性、坐标和明细不变；这一轮按要求改变显示分组，因此不再要求分组与前一节相同。
- 同一份原始勘察加报文在 zoom 5 的全报文标记数：JMA 7 → 18，NTWC 3 → 24。它们是整个报文在该缩放级别的数量，实际窗口仍按视口裁剪。另一个原始 NTWC 小样本为 1 → 2。
- 三份原始样本的基础展示条目逐项一致；各自 19 个整数缩放级别的所有标记外接框检查均无重叠。44 项 Rust 海啸测试及 32 项 Flutter 专项检查通过，包含左下 2 格上限、12 秒轮播、地图缩放与点击、无额外文字重建。

## 默认视角可读性调整（2026-10-22）

- 根据安装后截图，前一版连文字一起缩到默认视角约 29px 柱高，无法正常阅读。提高最小显示比例并放缓缩放曲线：zoom 5 柱体约 75px，zoom 6 约 82px，近景上限约 88px，最小约 68px。保留地图缩放，避免重新增长至原来 104px 柱高。
- Rust 聚合使用相同尺寸曲线及 6px 间隔，有效测站仍在各级参与，组件复用与左下最多 2 格不变。较大的实际标记会重新准备相应分组，以免扩大后重叠，不会用旧小尺寸的分组强行绘制大标记。
- 44 项 Rust 海啸测试、31 项 Flutter 水位计／左下列表测试通过；验证更新后的实际绘制高度、连续缩放、坐标及点击、无地图帧上的文字重建。
