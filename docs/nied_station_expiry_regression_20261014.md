# NIED 测站到期通知与 EEW 录制的性能回归

## 已确认的触发链

测站的 10.5 秒保持时间各自到期时，会调用
`ShakeDetectionService._handleStationExpired()`。旧实现每次都立即重算检测网格、
发布检测快照；地图监听器随后调用 `_captureStationFrame('nied')`。
EEW 录制期间，每次发布都会重新构造并冻结整个测站网络的 JSON 快照。

同一批上百个保持计时器到期时，这条链会重复执行上百次。
完整 APP 的 CPU 采样确认了这条调用链。峰值堆采样中，
`_SourcePayloadSnapshot` 达到 1,084,670 个，Dart 堆使用量达到 628,317,376 字节。
同一轮 Rust 分配峰值为 13,394,248 字节，不能把这次 GB 级增长归为 Rust 数值状态持有。

## 修复边界

- 每个测站仍按原来的 10.5 秒期限解除保持状态。
- 同一短时间内的到期通知合并到 16 毫秒内发布一次。
- 真实新帧或周期检查已包含到期状态时，取消待发布的重复通知。
- 重置、更换测站目录时取消旧的待发布任务。
- 每个原始观测帧继续处理和保存；震源算法、观测数值、报文、波圈样式不变。

## 完整 APP 对照

使用已保存的 2026-10-13 紀伊水道事件：4 报 Jian JMA EEW，
以及 20:43:00–20:48:20 JST 窗口内实际保存的 288 个地表震度 GIF。
保持原始 GIF 字节和文件名观测时间，从 GIF 重新解析测站输入。
报文使用已保存的原始负载及接收顺序。播放时的测站接收时间由独立测试时钟生成。
已有文件中的缺帧保留原来的时间间隔。

测试包含完整地图、统一 UI、推算、测站保持计时器、EEW 历史录制、GIF 录制，
结束后额外等待 40 秒。其他上游网络隔离，参数和设置在副本中运行。
对照的 Rust DLL SHA-256 完全一致；新增 KA 空间检测迁移未混入这次对照。

## 结束后的常驻占用

修复后的无中途堆采样运行，在等待 40 秒后仍约 538 MiB；
继续空闲后，Windows 工作集检查约 447 MiB。
同一二进制的无输入对照约 336 MiB。
该次 Windows 工作集分类中，私有页约 335 / 233 MiB，
映像页约 98 / 91 MiB，映射页约 13 / 12 MiB（事件后 / 无输入）。

Dart 堆实际使用量为事件后约 64.57 MiB、无输入约 54.10 MiB；
事件后堆容量约 108.31 MiB。Rust 当前分配约 3.35 MiB。
这些数据说明主要瞬时峰值已消除，但结束后的全部额外常驻内存尚未逐项归属，
不能据此宣称全部回收问题已经解决，也没有使用工作集裁剪来制造下降。

## 检查

- 192 站同时到期仅发布一次合并快照，并验证保持期限和原始观测字段。
- 新观测到达时取消待发布的到期通知。
- 重置时取消待发布任务及计时器。
- 连同冷启动检测、手机测站对象替换、报警门控共 15 项测试通过。
- 变更文件定向 Dart 分析无问题。
